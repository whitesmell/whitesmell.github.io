子非AI观点
GPT-5.5 最值得关注的，不是某个单点能力再次刷新，而是 GPT-5 系列的能力重心变得更清晰：从单次输出，走向长程任务；从内容生成，走向工具协同；从局部辅助，走向可验证的工作推进。

这次升级主要集中在五个方向：长程编码、长上下文、电脑操作、职业任务、科研协作。Terminal-Bench 2.0 从 GPT-5.4 的 75.1% 提升到 82.7%，Expert-SWE 从 68.5% 提升到 73.1%，Graphwalks BFS 1M 从 9.4% 提升到 45.4%，MRCR v2 512K-1M 从 36.6% 提升到 74.0%。

这些变化说明，GPT-5.5 的重点不是“单点炫技”，而是在更长上下文、更复杂工具链、更真实任务流中提升稳定性。它不是低价模型，也不是所有任务都适合使用的万能模型；它更适合高价值、长链路、可复核的复杂任务。

01 GPT-5.5 到底升级了什么？

GPT-5.5 不是 GPT-5.4 的常规增强版。

它更像是 GPT-5 系列面向真实工作流的一次强化：不再只优化生成质量，而是优化任务能否持续推进。它被同时放进 ChatGPT 和 Codex 两个入口，本身就说明它的主战场不是轻量交互，而是更复杂的真实任务：读代码库、处理多文档、调用工具、分析数据、改文件、生成报告、验证结果。

更准确地说，GPT-5.5 是一个面向 agentic work 的模型。

它的能力变化可以拆成三层。

第一层，是更强的任务保持能力。它能在长任务中更稳定地记住目标、约束、上下文和中间状态，不容易在多轮执行里丢失方向。

第二层，是更强的工具协同能力。它更擅长使用浏览器、代码环境、文件、表格、命令行和业务软件，把任务推进到可交付结果。

第三层，是更高的复杂任务效率。它不是所有场景都更便宜，但在大代码库、长文档、复杂流程和科研分析中，有机会通过减少重试和返工来摊低总成本。

一句话概括：GPT-5.5 的关键词不是“表达能力升级”，而是“复杂任务推进能力升级”。

02 GPT-5.5 的本体信息：版本、上下文、入口与价格

先看 GPT-5.5 本身。

这次发布包含 GPT-5.5 和 GPT-5.5 Pro 两个层级。GPT-5.5 面向 ChatGPT 和 Codex 场景开放，覆盖 Plus、Pro、Business、Enterprise 等用户；GPT-5.5 Pro 面向更高难度任务。

上下文方面，Codex 中 GPT-5.5 支持 400K 上下文；API 计划支持 1M 上下文。这个信息很关键，因为 GPT-5.5 的核心能力不是短任务，而是更长链路、更大材料、更复杂工具流中的持续处理。

价格方面，它不是低价模型。标准 API 为输入 5 美元/百万 tokens、输出 30 美元/百万 tokens；GPT-5.5 Pro 为输入 30 美元/百万 tokens、输出 180 美元/百万 tokens。Codex Fast mode 速度提升 1.5 倍，但成本是 2.5 倍。

这决定了 GPT-5.5 的定位：它不适合被当作普通内容生成模型来使用，更适合放进高价值复杂任务里。

比如：

  • • 大代码库修复、迁移、重构、测试补齐；
  • • 长文档审阅、财务文件处理、法务材料分析；
  • • 复杂客服、销售运营、CRM 更新、流程分流；
  • • 科研数据分析、实验结果解释、研究工具搭建；
  • • 需要长上下文、多工具、多步骤执行的 Agent 工作流。

GPT-5.5 的价值，不应该只用“每百万 tokens 多少钱”判断，而要看一个任务最终花了多少钱、节省了多少人工、减少了多少返工。

04 两项关键升级：长程编码与长上下文

GPT-5.5 的第一条主线，是长程编码。

Terminal-Bench 2.0 达到 82.7%，Expert-SWE 达到 73.1%，SWE-Bench Pro 达到 58.6%。这些指标更接近真实工程环境：命令行操作、多文件修改、真实 issue、长周期任务、工具协同，而不是测试模型能否完成一个孤立函数。

GPT-5.5 的编码进步，核心在于工程闭环能力增强。

真实软件工程不是生成代码片段，而是读懂仓库结构，理解失败原因，定位改动边界，处理多文件依赖，运行测试，理解报错，再继续修复。真正难的不是生成代码，而是判断为什么改、改哪里、改完会影响什么。

第二条主线，是长上下文。

过去很多模型都宣传大上下文窗口，但真正的问题不是“能装多少材料”，而是“装进去以后还能不能正确追踪、关联和推理”。GPT-5.5 在这方面的变化非常明显：Graphwalks BFS 1M 从 GPT-5.4 的 9.4% 提升到 45.4%，MRCR v2 512K-1M 从 36.6% 提升到 74.0%。

这不是简单容量增加，而是长材料中的结构化处理能力提升。

长上下文对 GPT-5.5 的意义很大：它让模型更适合处理大代码库、长文档链路和多轮 Agent 任务。对 Agent 来说，上下文不是“资料仓库”，而是工作记忆。它要记住任务目标、约束、历史动作、失败原因和下一步计划。

所以，GPT-5.5 的长上下文进步，本质上是在为长程 Agent 铺底座。

05 职业任务、电脑操作、科研协作：三条副线合成一个方向

GPT-5.5 的后续能力可以合并看：职业任务、电脑操作和科研协作，本质上都指向同一个方向——模型进入真实工作流。

职业任务上，GDPval 达到 84.9%，Tau2-bench Telecom 达到 98.0%。典型案例包括分析数月演讲请求数据、建立评分和风险框架；审阅 24,771 份 K-1 税表、共 71,637 页，并将周期提前两周。

这类任务的共同特征是：材料多、规则多、流程长、结果要复核、人工成本高。它们不是轻量生成任务，而是复杂业务链路。

电脑操作上，OSWorld-Verified 达到 78.7%，BrowseComp 达到 84.4%，GPT-5.5 Pro 在 BrowseComp 上达到 90.1%。这意味着模型不只是文本交互能力提升，而是更能进入浏览器、终端、表格、文档、后台系统等真实软件环境。

科研协作上，GeneBench、BixBench、FrontierMath Tier 4 都有提升。GPT-5.5 还展示了从 prompt 构建数学可视化工具的能力。这类进展不意味着它替代科学家，但说明它正在压缩科研中的执行层：数据处理、代码实现、工具构建、初步分析、结果整理。


这张图展示的是 GPT-5.5 在科研工具生成中的一个案例：模型从研究者的 prompt 出发，在短时间内构建代数几何可视化应用，用于展示二次曲面交线并转换为 Weierstrass 模型。它说明 GPT-5.5 的能力不只是解释概念，而是把专家意图转成可运行工具。


把这三条线放在一起看，GPT-5.5 的方向就很清楚：

它不是为某一个岗位优化，而是为“可拆解、可执行、可验证”的复杂任务优化。

06 价格争议：它不是低价模型，而是高价值任务模型

GPT-5.5 的价格不低，这一点不能回避。

标准 API 输入 5 美元/百万 tokens、输出 30 美元/百万 tokens；Pro 版输入 30 美元/百万 tokens、输出 180 美元/百万 tokens。Codex Fast mode 更快，但成本也更高。

因此，把 GPT-5.5 理解成“低价模型”并不准确。它更像高价值任务模型。

判断它值不值，不看一句“更强”，只看四个问题：

这个任务原本要多少人天？
模型一次完成率有多高？
人工复核要多久？
出错成本有多大？

如果是普通改写、轻量总结、简单问答，GPT-5.5 可能显得贵。
如果是大代码库、长文档、复杂流程、高人工成本任务，它才可能通过减少重试、返工和复核来摊薄总成本。

GPT-5.5 逼着行业从 token 单价，转向任务总成本。

07 边界：强，但不能神化

GPT-5.5 值得重视，但不能神化。

第一，它不是所有榜单都第一。在部分编码、工具调用和长上下文任务上，其他前沿模型仍有领先项。前沿模型竞争已经进入多模型分工阶段，而不是单一模型通吃。

第二，GPT-5.5 Pro 不适合所有任务。高成本模型应该用于高价值、高复杂度、高不确定性的任务，而不是普通内容处理。

第三，长上下文不等于自动理解。1M context 能放更多信息，但如果输入混乱、目标模糊、验证缺失，仍然会产出看似完整但不可用的结果。

第四，执行能力越强，越需要质量控制。模型能改代码、处理文件、调用工具，也意味着错误可能直接进入工作流。测试、复核、日志、权限、回滚，仍然是企业落地的底座。

GPT-5.5 应该被看作强执行者，而不是最终责任人。

08 企业和创业者该怎么看：不是接入模型，而是重算工作账本

GPT-5.5 不应该被当成一个“更高级的通用入口”。

它更像一次提醒：当前沿模型开始具备长上下文、工具调用、电脑操作和多步执行能力，企业不能再只按“人均账号数”衡量 AI 化程度，而要重新审视每一类工作的成本结构。

哪些工作值得交给 GPT-5.5 这类模型？判断标准不复杂：

任务足够长，模型才有发挥空间；
材料足够多，长上下文才有意义；
人工足够贵，模型成本才可能被摊薄；
结果可验证，模型产出才敢进入流程。

如果只是普通内容处理、轻量总结、短文本改写，使用 GPT-5.5 很可能是过度配置。真正值得测试的，是大代码库重构、财务与法务文件审阅、复杂客服工单、投研材料整理、科研数据分析、跨系统运营流程等长链路任务。

企业需要的不是“把 GPT-5.5 接进来”，而是先回答一个更朴素的问题：

这件事过去要多少人天？
模型介入后能减少多少重试？
人工复核是否真的下降？
错误成本是否可控？
流程能不能沉淀复用？

这些问题答不清，模型再强也只是更昂贵的实验。

对创业者来说，GPT-5.5 也不是单纯利好。前沿模型越强，浅层功能越危险。普通总结、轻量写作、简单问答、通用代码生成，都会不断被底层模型吞掉。

真正留下来的，不是“包装模型能力”的产品，而是能控制任务闭环的产品：有行业数据，有真实流程，有验收标准，有复核机制，有责任边界。

模型升级会抬高天花板，也会压低浅层应用的地板。这是 GPT-5.5 留给 AI 创业者最现实的压力。

09 结语：GPT-5.5 不是答案，而是一道分水岭

GPT-5.5 不是 AGI，也不是万能模型。

它更像一道分水岭：前沿模型的竞争，不再只看单轮能力、知识广度或表达质量，而是开始进入更难的阶段——能否在复杂上下文里保持目标，调用工具，处理长链路任务，并把结果推进到可验证状态。

它价格不低，也并非所有任务都适合使用。用在短任务上，可能是浪费；用在缺少验证流程的任务上，可能制造风险；用在复杂但可复核的高价值任务上，才可能体现差异。

最终问题很简单：

GPT-5.5 能不能把一个复杂任务更稳定、更可控、更低返工地完成？

这个问题，比任何宣传词都重要。
