Anthropic 发布了升级版的 Claude 3.5 模型，包括 Claude 3.5 Sonnet 和 Claude 3.5 Haiku。升级后的 Sonnet 模型在编码能力上有显著提升，超越了所有公开模型，包括 OpenAI 的 o1-preview。Haiku 模型则在性能与 Claude 3 Opus 持平的同时，成本更低，速度更快。最引人注目的是，Claude 3.5 Sonnet 率先推出了“计算机使用”功能的公测版，使开发者能够引导 Claude 像人类一样使用计算机，标志着 AI 迈向通用人工智能的重要一步！

Claude 3.5 Sonnet：编码能力比肩专业软件工程师

Anthropic 最新发布的 Claude 3.5 Sonnet 模型在多个行业基准测试中表现出色，尤其是在代理编码和工具使用任务方面取得了显著进步。

1. 编码能力大幅提升，超越 o1-preview

在编码方面，Claude 3.5 Sonnet 在 SWE-bench Verified 上的性能从 33.4% 提升到 49.0%，超过了所有公开模型，包括以推理能力著称的 OpenAI o1-preview 以及专门为代理编码设计的系统。这意味着 Claude 3.5 Sonnet 能够理解更复杂的编程问题，生成更准确、更完整的代码，其编码能力已经可以比肩甚至超越专业的软件工程师。

2. 工具使用能力显著增强

在代理工具使用任务 TAU-bench 上，Claude 3.5 Sonnet 在零售领域的性能从 62.6% 提升到 69.2%，在更具挑战性的航空领域则从 36.0% 提升到 46.0%。这表明 Claude 3.5 Sonnet 不仅能够生成代码，还能够理解代码的功能，并将其应用于解决实际问题，其工具使用能力也得到了显著增强。

3. 客户反馈积极，多家公司受益

GitLab 将 Claude 3.5 Sonnet 用于 DevSecOps 任务测试，发现它在推理能力上提升了 10%，且没有增加延迟，是支持多步骤软件开发流程的理想选择。Cognition 公司将新模型用于自主 AI 评估，与之前的版本相比，在编码、规划和问题解决方面都取得了实质性的改进。The Browser Company 将该模型用于自动化基于网络的工作流程，并指出 Claude 3.5 Sonnet 的表现优于他们之前测试过的所有模型。这些来自真实用户的积极反馈，充分证明了 Claude 3.5 Sonnet 在实际应用中的强大能力。

Claude 3.5 Haiku：低成本、高速度、高性能的完美结合

Claude 3.5 Haiku 是 Anthropic 最快模型的下一代版本。它在成本和速度与 Claude 3 Haiku 相同的情况下，在各项技能上都有所提升，甚至在许多智能基准测试中超过了上一代最大的模型 Claude 3 Opus。这意味着开发者和用户可以在不增加成本和延迟的情况下，获得更强大的 AI 能力。

1. 编码能力出众

Claude 3.5 Haiku 在编码任务上表现尤为出色。例如，它在 SWE-bench Verified 上的得分高达 40.6%，优于许多使用公开可用的最先进模型的代理，包括最初的 Claude 3.5 Sonnet 和 GPT-4o。这使得 Claude 3.5 Haiku 成为轻量级编码任务的理想选择，例如实时代码补全、代码调试等。

2. 适用于多种应用场景

凭借低延迟、改进的指令遵循和更准确的工具使用，Claude 3.5 Haiku 非常适合面向用户的产品、专门的子代理任务以及从海量数据（如购买历史、定价或库存记录）生成个性化体验。例如，开发者可以使用 Claude 3.5 Haiku 构建聊天机器人、智能助手等应用，为用户提供更快速、更准确的响应。

颠覆性的“计算机使用”功能：AI 迈向通用人工智能的重要一步

Anthropic 为 Claude 3.5 Sonnet 模型引入了一个全新的功能：计算机使用。开发者可以通过 API 引导 Claude 像人类一样使用计算机，包括查看屏幕、移动光标、点击按钮和输入文本。 这是 AI 领域的一项重大突破，标志着 AI 迈向通用人工智能的重要一步！

1. 像人一样使用计算机

“计算机使用”功能让 AI 能够像人类一样使用各种标准工具和软件程序，而不仅仅是完成特定的任务。 开发者可以使用这个新功能自动化重复性流程、构建和测试软件以及执行开放式任务，例如研究。 这意味着 AI 的应用范围将得到极大的扩展，可以处理更复杂、更灵活的任务。

2. “计算机使用”场景举例

假设用户需要整理一份市场调研报告，需要收集多个网站上的数据，并将数据整理到 Excel 表格中。这项任务需要用户打开多个网页，复制粘贴数据，手动调整格式，非常耗时费力。

借助“计算机使用”功能，用户可以指示 Claude 代为完成以下步骤：

  1. 1. 数据收集: Claude 使用 Computer 工具打开浏览器，访问用户指定的网站，并使用 Text Editor 工具将网页上的关键数据提取出来，例如产品价格、用户评价等。

  2. 2. 数据整理: Claude 使用 Computer 工具打开 Excel 软件，并将提取的数据整理到表格中，并根据需要调整格式，例如添加标题、排序、计算平均值等。

  3. 3. 生成报告: Claude 可以根据用户提供的模板，自动生成完整的市场调研报告，包括图表、分析结论等。

通过 Claude 的帮助，用户可以从繁琐的数据收集和整理工作中解放出来，专注于报告的分析和撰写，大大提高工作效率。

3. 人、LLM 和本地计算机的职责和交互流程

为了更清晰地理解“计算机使用”功能的工作原理，我们以一个具体的场景为例，说明人、LLM 和本地计算机在该场景中的职责和交互流程。

场景： 用户需要填写一份网页上的供应商申请表单，表格申请对象为“Ant Equipment Co.”公司，所需数据可以从第一个窗口（左侧窗口）打开的Excel供应商电子表格中获取，或者通过第一个窗口的搜索门户网站标签页搜索获取。用户要求 Claude 在第二个窗口（右侧窗口）中填写表格。

交互流程：

  1. 1. 人: 向 Claude 发出指令：'''Please fill out the vendor request form for 'Ant Equipment Co.' using data from either the vendor spreadsheet or search portal tabs in window one. List & verify each field as you complete the form in window two.'''

  2. 2. LLM (Claude): 接收用户的指令，并将其分解成一系列可执行的步骤：

    • • 使用 Computer 工具识别第一个窗口中打开的Excel供应商电子表格和搜索门户网站标签页的位置。

    • • 尝试从 Excel 电子表格中查找“Ant Equipment Co.”公司对应的数据。

      • • 如果找到，则提取公司名称、地址、联系方式等信息。

      • • 如果没有找到，则使用 Computer 工具切换到搜索门户网站标签页，输入“Ant Equipment Co.”进行搜索，并从搜索结果中提取相关信息。

    • • 使用 Computer 工具切换到第二个窗口，并定位到供应商申请表格。

    • • 根据网页表单的结构，使用 Computer 工具操作鼠标点击相应的输入框，并将提取到的字段信息逐个填写到表格中。

    • • 在填写每个字段后，使用 Computer 工具截取屏幕截图，并生成文本描述，列出已填写的字段和对应的信息，例如：“公司名称：Ant Equipment Co.”。

  3. 3. 本地计算机: 执行 Claude 发送的指令，例如打开窗口、定位文件/标签页、读取文件内容/搜索信息、定位网页表单、填写表格、截取屏幕截图等。

  4. 4. LLM (Claude): 在填写完所有字段后，使用 Computer 工具截取完整表格的屏幕截图，并生成最终的文本描述，列出所有已填写的字段和对应的信息。

  5. 5. 人: 接收 Claude 的最终结果，包括所有已填写字段的列表和验证信息，以及完整表格的屏幕截图。

4. 如何实现？

“计算机使用”功能通过 API 使 Claude 能够感知和与计算机界面交互。开发者可以集成此 API，使 Claude 能够将指令（例如，“使用我的计算机和在线数据填写此表格”）转换为计算机命令（例如，检查电子表格；移动光标以打开网络浏览器；导航到相关网页；使用来自这些网页的数据填写表格；等等）。

5. Anthropic 定义的工具

为了使 Claude 能够有效地使用计算机，Anthropic 提供了一组预定义的工具。

这些工具由 Anthropic 定义，但开发者需要显式地评估工具的结果并将 tool_results 返回给 Claude。

目前提供的 Anthropic 定义的工具有：

  • • { "type": "computer_20241022", "name": "computer" }

  • • { "type": "text_editor_20241022", "name": "str_replace_editor" }

  • • { "type": "bash_20241022", "name": "bash" }

type 字段用于标识工具及其参数以进行验证，name 字段是向模型公开的工具名称。

如果要提示模型使用其中一种工具，则可以按 name 字段显式引用该工具。 name 字段在工具列表中必须是唯一的；您不能在同一个 API 调用中定义与 Anthropic 定义的工具同名的工具。

我们不建议定义与 Anthropic 定义的工具同名的工具。 虽然您可以使用这些名称重新定义工具（只要工具名称在您的 tools 块中是唯一的），但这样做可能会导致模型性能下降。

(1) Computer 工具

Computer 工具用于与计算机交互，例如移动鼠标、点击按钮和截取屏幕截图。

建议不要发送分辨率高于 XGA/WXGA 的屏幕截图，以避免与图像大小调整相关的问题。

下表列出了 Computer 工具的参数：

参数描述
display_width_px必填 模型控制的显示器的宽度（以像素为单位）。
display_height_px必填 模型控制的显示器的高度（以像素为单位）。
display_number可选 要控制的显示器编号（仅与 X11 环境相关）。如果指定，则该工具将在工具定义中提供显示器编号。

(3) Bash 工具

Bash 工具用于在 bash shell 中运行命令，为 Claude 提供更底层的系统操作能力。

下表列出了 Bash 工具的参数：

参数描述
command要运行的 bash 命令。除非正在重新启动该工具，否则这是必需的。
restart指定 true 将重新启动此工具。否则，请不要指定此项。

Bash 工具的核心代码逻辑:

async def run(self, command: str):
    """在 bash shell 中执行命令。"""
    # 使用 asyncio.create_subprocess_shell 创建 bash 进程
    process = await asyncio.create_subprocess_shell(
        command,
        stdin=asyncio.subprocess.PIPE,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
    )

    # 将命令发送到 bash 进程
    process.stdin.write(command.encode() + b'\n')
    await process.stdin.drain()

    # 读取 bash 进程的输出结果
    stdout, stderr = await process.communicate()

    # 返回输出结果和错误信息
    return stdout.decode(), stderr.decode()
