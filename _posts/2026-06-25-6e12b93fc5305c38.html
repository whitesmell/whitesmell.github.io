导读：微软CEO萨提亚·纳德拉近期连续谈到人力资本、智能资本与OpenAI关系变化。真正的警告不是谁拥有最强模型，而是企业使用AI后，经验、评估和纠错留在谁手里。本文把学习权拆成目标、轨迹、反馈、评估和路由，并给出一张可直接复盘 AI 项目的学习回路表。

你们公司用了半年人工智能工具。周报更快了，客服回复更顺了，销售邮件也像那么回事了。但我想问一个有点扎心的问题：

这半年过去，到底是谁变聪明了？

是员工？是公司自己的系统？还是那个你每个月付费调用的外部模型？

这不是一句鸡汤式反问，也不是“微软终于要摆脱 OpenAI”的关系八卦。微软掌门人萨提亚·纳德拉最近连续几次长谈，绕来绕去其实都在讲这件事：智能时代最危险的事，不是你没有接入最强模型，而是你每天使用模型产生的经验，没有留在自己的系统里。

我愿意把它叫作：学习权。

每一次模型调用，每一次人工纠错，每一次评估打分，每一次流程改造，都会产生经验。沉淀在你这里，它就是资产；只沉淀在别人那里，它就会变成长期租金。

先把结论放前面：

  • • 智能资本不是调用量，而是你能不能把工作经验压缩成可复用资产。
  • • 学习权不是一句口号，而是目标、轨迹、反馈、评估和路由的控制权。
  • • AI 项目上线以后，最该复盘的问题不是省了几小时，而是谁因为这次使用变聪明了。

智能资本，不是买了多少调用量

纳德拉在播客访谈里先聊了一个看起来很远的话题：诗。

他说，诗歌和代码很像，本质都是压缩。短引一句：

“compression in its best form”

最好的压缩形式

这不是文艺闲聊。好的诗把复杂的人类经验压缩成几行字。好的代码把复杂逻辑压缩成可以运行、可以复用的结构。一家公司的经营能力，其实也是一种压缩。

老销售怎么判断客户是真有预算，还是只想套方案；资深客服怎么听出用户真正生气的点；工程师怎么闻到一个架构设计三个月后会炸；法务怎么判断一条合同红线能不能退。很多东西不在标准流程里，不在数据库字段里，也不在财务报表上。

这些就是隐性知识。纳德拉把人力资本和智能资本放在一起讲，关键不是说人力资本不值钱了，而是说人的判断、品味、反馈、纠错，可以被模型系统化，变成机器能复用、组织能复利的智能资产。这个智能资本，就是他原话里的 Token Capital。

所以智能资本不是接口账单里的消耗量，也不是“我们买了多少模型账号”。

它更像一组企业自己的智能资产：上下文、工作轨迹、人工反馈、私有评测、流程记忆、可复用技能、路由策略，甚至在某些场景里包括小模型权重。

换句话说，智能资本的本质不是“花掉调用额度”，而是把公司的判断压缩成可复用的能力。

学习权到底是什么

“学习权”听起来有点抽象，我把它拆成五样东西。

第一，目标。你到底要优化什么？销售邮件不是“写得礼貌”就好，而是能不能让高意向客户愿意进入下一步。

第二，轨迹。模型做这件事时用了哪些上下文，调用了哪些工具，走了哪些步骤，哪里失败过。

第三，人工反馈。人为什么接受，为什么驳回，为什么改成另一个版本。

第四，私有评估。你们公司自己判断好坏的标准，而不是公开榜单上的通用分数。

第五，路由和奖励策略。什么任务用最强模型，什么任务用小模型，什么情况必须人工确认，什么结果要被强化。

举个很普通的例子。

一个销售团队开始用模型写客户跟进邮件。半年后，真正有价值的不是那几百封邮件本身，而是：哪些客户会回复，哪些话术有效，主管为什么把某些邮件打回，哪些行业不能用太激进的承诺，哪些线索值得继续追。

如果这些反馈只留在外部工具里，或者合同和产品设计不允许你导出、复用、迁移，公司就可能变成一种尴尬角色：付费帮别人完善销售大脑，自己的系统却没有变聪明。

再看现在很流行的智能体工程工作法：先写计划文档，再让几个智能体分头研究代码、查文档、看历史方案，最后由人做判断和重新指挥。这个方法真正厉害的地方，不是“多开几个智能体很酷”，而是它把一次工作的目标、过程、验收标准、修改意见都留下来了。

计划文档里有目标，智能体执行记录里有轨迹，人的审稿和驳回是人工反馈，验收清单是私有评估，下一次任务怎么分给哪个模型，是路由策略。

这就是一个很小的学习回路。

问题是，这个回路最后归谁？

微软先给自己留了后手

微软和 OpenAI 这次协议调整，最容易被写成一出分手戏。

但这不是分手。

更准确地说，是独家押宝时代结束了。

关键事实可以压缩成两段。

2025 年 10 月，OpenAI 完成公司结构重组，微软获得 OpenAI Group PBC 约 27% 股权；OpenAI 承诺额外采购 2500 亿美元 Azure 服务；微软对 OpenAI 模型和产品的知识产权权利延长到 2032 年，并覆盖通用人工智能之后的模型。那一版协议里，OpenAI 的 API 产品仍在 Azure 独家框架里，非 API 产品开始有更多云服务空间；微软不再拥有 OpenAI 算力供应的优先拒绝权，也可以独立或与第三方追求通用人工智能。

到了 2026 年 4 月，关系又松了一扣：OpenAI 可以把所有产品服务给任意云上的客户；微软到 2032 年的授权变成非独家；微软不再向 OpenAI 支付收入分成；OpenAI 继续向微软支付收入分成到 2030 年，但有总额上限。Azure 仍是主要云伙伴，OpenAI 产品仍优先上 Azure。

所以，微软不是把 OpenAI 放走了。

它是在保留合作收益的同时，降低单一模型依赖。

微软还持股，还合作，还能从 OpenAI 的成长里受益。但它也在做自己的模型路线、多模型路由、Foundry 平台、Copilot 工作台和智能体运行时。纳德拉在另一场长访谈里谈 MAI、自有模型谱系、单位成本和单位能耗下的推理产出，表面是产品和基础设施，底层是一个更冷的判断：

不能把公司的未来挂在唯一模型供应商身上。

连微软都这么想，普通企业更该问问自己：我们是不是正在把最重要的学习回路，交给一个无法替换的外部系统？

最危险的不是文件泄露

纳德拉讲隐性知识时，用了一个很重的词：

“one-way door”

单向门

他的意思是，如果企业的隐性知识泄露出去，很难再收回来。

这和传统数据安全不完全一样。传统数据安全盯的是文件有没有出域，客户名单有没有泄露，权限有没有越界。这些当然重要，但智能时代还有一个更隐蔽的问题：你的工作方式、纠错方式、评估标准和业务品味，被谁拿走了？

一个客服智能体学会你们哪些用户不能硬怼，一个代码智能体学会你们团队讨厌过度抽象，一个投研智能体学会你们如何判断一家公司是不是“讲故事大于真增长”。这些不是单个文件，它们是组织经验。

所以企业用模型，不能只问“数据会不会被训练”。还要问：提示词、输入输出、人工修改、拒绝案例、成功案例、审批轨迹、工具调用日志、评估样本，最后留在哪里？

如果合同、接口和产品设计让这些轨迹只沉淀在外部平台里，而你自己的系统没有变聪明，那就不是智能转型。

那是把学习外包。

新 BASIC 不是大模型

微软第一个产品是 BASIC 解释器。Reid Hoffman 问纳德拉，智能时代的新 BASIC 是什么。

纳德拉的答案不是 GPT，不是 Copilot，也不是某个模型名字。

他讲的是“爬山机器”。

翻译成人话，就是企业围绕目标、数据、反馈、评估、奖励，搭一台持续爬坡的机器。系统每跑一轮，都更接近你的业务结果一点。

比如代码审查。第一次智能体只会挑语法错误；第二次，它知道你们支付模块必须多测边界条件；第三次，它记住你们团队不喜欢为了模式而模式；第十次，它开始能把“这个改动以后会让维护者很痛苦”这种老工程师直觉，变成可复用的审查标准。

这才是爬坡。

纳德拉也把私有评估讲成企业的新知识产权。公开榜单只能告诉你模型在通用题上强不强，不能告诉你一个销售建议是否符合你的客户策略，也不能告诉你一个合同修改是否符合你的风险偏好。

所以，未来企业的关键能力不是“我接了几个模型”，而是“我有没有自己的评估标准”。

没有评估，就没有真正的学习。

别拿最贵模型硬怼普通问题

这里还有一个很现实的坑：很多公司把“更强模型”当成唯一答案。

纳德拉在访谈里反复提醒，企业不要默认用前沿模型解决所有问题。很多任务并不是前沿问题，硬上最贵模型，未必更聪明，可能只是更贵。

企业里大量任务并不是开放式科学发现，而是重复、稳定、可评估的流程：报销审核、合同条款比对、售后分类、销售线索打分、会议准备、代码小修、权限检查。

这类任务真正需要的，可能不是每次都调用最贵模型，而是小模型加内部轨迹，加清楚的评估，加可控的权限和审计。

这也是纳德拉为什么反复谈智能供应链。

以后企业不会只问“哪个模型最强”。它会问：这个任务需要前沿推理吗？能不能用更小的模型？能不能本地跑？失败成本有多高？这次调用产生的轨迹，能不能变成下次的能力？一百万个调用单位花出去，换回的是一次性结果，还是新的组织资产？

每美元、每瓦能产出多少模型输出，听起来像基础设施指标，其实是经营指标。

当智能体 24 小时运行，模型调用不再是试验费用，而是生产成本。更要命的是，如果轨迹、反馈和评估都留在供应商系统里，而你没有可导出的样本、可复用的评估和可迁移的流程经验，账单越大，依赖越深。

软件没有死，旧边界死了

Stratechery 里有个问题很有意思：软件死了吗？

我觉得纳德拉的回答可以翻译成一句话：软件没有死，旧式软件服务的边界死了。

过去的软件把数据模型、业务逻辑、界面和收费方式绑在一起。人登录系统，点按钮，录数据，公司按席位付费。智能体出现后，这套结构会松动，因为智能体不需要一直看按钮，它需要接口、权限、上下文、工具调用、可验证结果和可审计轨迹。

GitHub Copilot 从自动补全，到聊天，到智能体模式，再到自动提交代码合并请求、人类验收，就是一个预告。Copilot App、Canvas、Project Solara 这些微软名字不重要，重要的是方向：未来人不是在线性聊天框里和一个模型对话，而是在一个工作台里管理一群长期运行的智能体。

智能体越像员工，越需要工牌。它要有身份，知道代表谁工作；要有权限，知道能看什么、能改什么、能不能发外部邮件；要有沙箱，尤其是会生成代码、访问文件系统、联网操作的时候；也要有审计轨迹。出了问题，不能只说“模型这么干的”。

这也是 Agent 365、Foundry、企业 Copilot 这些产品背后真正的问题。别把它们当发布会广告看，它们在指向一个行业变化：智能工具会变成数字员工，数字员工需要运行时、权限系统、审计系统和成本账本。

收费也会变。纯席位模式不够了，因为智能体会持续消耗推理、检索、工具调用和验证成本。未来更可能是“按席位 + 按用量”的混合模式。

这会逼财务负责人也加入智能战略讨论。

人不能只当验收按钮

还有一个容易被忽略的词：认知覆盖率。

代码有测试覆盖率。智能体做事以后，人也要有认知覆盖率：它做了什么，我是否理解；它为什么改成这样，我是否能解释；它绕过了哪些判断，我是否知道。

这点很关键。学习权不只是防外部供应商，也防组织内部变笨。

如果员工只会点“接受”，不会追问模型为什么这么做，企业表面效率提升，实际知识肌肉会萎缩。几年后你会发现，流程自动化了，但没人知道流程为什么这样设计。

所以一把手不能再把人工智能当 IT 项目。

纳德拉说人工智能是公司的未来形态。我同意这个判断。很多企业现在的智能战略，本质上是三件套：买账号，做试点，发新闻稿。客服接一个机器人，销售接一个写邮件工具，研发接一个代码助手，法务接一个合同审查软件。看起来热闹，实际没有统一的学习回路。

数据分散，评估分散，纠错分散，权限分散。最后形成一堆分散的小脑袋，没有长出企业自己的大脑。

一把手真正该问的不是“我们用了几个智能体”，而是：昨晚全公司模型处理过的任务，产生了哪些新知识？这些知识沉淀在哪里？哪些进入了评估集？哪些变成了工作流？哪些能迁移到下一个团队？哪些只留在供应商平台里，带不回来了？

这也能解释纳德拉谈人工智能主权时为什么不只讲数据驻留、国产模型和本地机房。主权的核心不是把门关上，而是一个经济体里的企业能不能用上前沿能力，同时把学习回路留在自己能控制、能审计、能迁移的系统里。

企业版也一样。你不需要幻想从零训练一个 GPT，大多数公司也没这个钱。但你必须知道自己的智能供应链长什么样：模型来自谁，云来自谁，数据在哪，评估在哪，智能体运行时谁控制，权限谁定义，审计谁保留，人工纠错最后喂给谁。

这张链路图画不出来，就别说自己有智能战略。

也别把微软写成英雄

到这里要泼一盆冷水：支持纳德拉这个判断，不等于给微软写广告。

微软不是单纯“反对模型公司拿走企业学习回路”。更准确地说，它正在把企业学习回路包装成自己的平台战略。M365、GitHub、Copilot、WorkIQ、智能体运行时、企业身份和权限系统，如果串起来，也会成为企业记忆和智能体工作流的入口。

所以企业不能从模型公司租大脑，又从平台公司租记忆。

这句话刺耳，但现实。模型公司希望靠更多调用改进模型，平台公司希望托管你的工作台，软件服务公司希望绑定你的业务流程。每一方都能给你效率；如果合同、接口和导出能力没有设计好，每一方也都可能让你的学习回路越来越难迁移。

你不是不能用它们，你要决定边界。

学习权如果不能迁移，就只是高级租赁。

今天就做一张表

这篇文章不是劝你别用人工智能。恰恰相反，越早用越好。

但别只会用，要会留。

这周就选一个高频流程：销售跟进、客服升级、代码审查、合同审核、财务报销、投研初筛，任选一个。

问五个问题。

第一，什么结果才算好？如果说不清目标，后面都是空的。

第二，智能体的工作轨迹留在哪里？只看最终答案，不够。

第三，人工驳回有没有变成可复用的反馈？一句“这个不行”如果没被记录，下次还会犯。

第四，你们有没有私有评估？别只看通用榜单，要有自己的验收题。

第五，换模型、换云、换平台时，路由策略、奖励规则、失败样本和工作流经验能不能带走？
