7 月 30 日，OpenAI 把 GPT-5.6 Luna 的 API 价格砍了 80%：每百万 token 输入从 1 美元降到 0.2 美元，输出从 6 美元降到 1.2 美元。

三周前发布的新模型，突然卖到原价的五分之一。这本来足够占据一整天的头条。

不到 24 小时，DeepSeek 在 7 月 31 日放出了 DeepSeek-V4-Flash-0731。它没有继续降价，却把一款更强的模型塞进了原来的价签：每百万 token 输入 0.14 美元，输出 0.28 美元。

在 Artificial Analysis 的独立评测里，它的综合指数是 50，只比降价后的 Luna 低 1 分，单任务成本却仍低约 60%。

一天之内，低价模型的价格锚被改写了两次。

这无法证明 DeepSeek 专门卡着 OpenAI 的时间发版，也没必要编一个“隔空交锋”的故事。更值得看清的是，两家公司正在争夺同一件东西：谁能用更低的成本，完成一次真正的 Agent 任务。

DeepSeek 这次没有新架构，没有更多参数，连网页端和 App 都没更新。它只把三个月前的 V4 Flash 重新做了一遍后训练，原生支持 Responses API，并针对 Codex 做了适配。

只看参数量，已经解释不了 Agent 能不能把事做完。


同一副骨架，为什么突然更会干活了？

先把产品说清楚。

DeepSeek-V4-Flash 是 V4 家族里偏速度和成本的版本。它采用 MoE 架构，总参数 2840 亿，但每次处理一个 token，只激活其中约 130 亿参数。上下文窗口是 100 万 token，最大输出 38.4 万 token，同时支持思考与非思考模式。

7 月 31 日进入 public beta 的 DeepSeek-V4-Flash-0731，是一次 API 公测更新。V4 Pro、网页端和 App 都没有换模型。开发者甚至不用改调用方式：Base URL 保持不变，把模型名设为 deepseek-v4-flash 即可。

官方把变化压缩成了一句话：

“Keeps the same model architecture and size… and was only re-post-trained.”

“与预览版保持相同的模型架构和规模，只重新进行了后训练。”

这句话比九项跑分更有分量。

因为它排除了最容易讲的故事：没有换架构，没有扩大参数规模，也没有重新预训练。**同样的架构和参数规模，经重新后训练后，在工具调用与 Code Agent 测试上表现大幅提升。**它具体被怎样训练，官方没有披露。

官方自测的成绩确实扎眼：

聊天模型交一份答案。

Agent 要交付一个结果。

独立评测，给出了第二张成绩单

厂商自测最怕一件事：模型和测试脚手架一起调，最后分数很好看，换个环境却复现不了。

所以更有意思的，是同一天发布的独立评测机构 Artificial Analysis 的结果。他们用 Intelligence Index v4.1 的九项测试重新跑了一遍 0731，指数从旧版的 40 升到 50，高于 V4 Pro 的 44；离当时 51 分的 GPT-5.6 Luna 和 GLM-5.2 只差 1 分，距离开源权重前沿 Kimi K3 的 57 分还有 7 分。

先说明白：这里的 50 是该机构综合九项评测算出的指数，不是“模型智商 50 分”，也不是放之四海皆准的绝对能力值。它更适合回答一个窄而重要的问题：换到同一套第三方规则下，新版是不是真的比旧版强？



图源：Artificial Analysis，数据截至 2026 年 7 月 31 日。

图里还有一条比名次更重要的信息：0731 落在了“智能指数—单任务成本”的帕累托前沿上。翻成人话，就是在这套测试里，很难找到一个既比它分高、完成任务又比它便宜的模型。

按该机构当日测算，它的平均单任务成本比 GPT-5.6 Luna max 低约 60%。这个数字不能直接套进每个真实项目，但至少说明，DeepSeek 这次没有单纯靠“多想、多吐 token”换分。

最能呼应 Agent 主线的，是 GDPval-AA v2。它考的不是一道算法题，而是一组接近真实工作的长任务。0731 的 Elo 从旧版的 1189 跳到 1559，超过 GLM-5.2 的 1510，仍低于 Kimi K3 的 1687。



图源：Artificial Analysis。

再看分项，九项评测的整体结果都比旧版高。第三方跑出的 Terminal-Bench 2.1 是 79%，低于官方 Harness 下的 82.7，但方向一致；银行客服 Agent 测试升到 31%，SciCode 升到 50%，Humanity's Last Exam 升到 37%。


图源：Artificial Analysis


这组数据没有证明“0731 全面登顶”，却补上了一块关键证据：提升不只存在于 DeepSeek 自己的 Harness 里。

后训练不是“补课”，而是练到能把事做完

预训练主要建立通用表征与基础能力。后训练更像在校准“遇到具体局面，下一步该做什么”。

拿修 Bug 来说，知道 Python、Git 和测试框架，只是起点。真正干活时，模型还要判断：先读哪个文件，要不要全局搜索，改动会不会牵连别处，测试失败后是代码错了还是环境错了，什么时候该停下来重新规划。

这不是背更多知识，而是形成一套动作习惯。

V4 的技术报告曾披露过一条思路：针对代码、数学、Agent 等领域分别训练专家，再通过 On-Policy Distillation，把这些领域专长整合回统一模型。

但 0731 版本到底换了哪些数据、奖励规则和训练配方，DeepSeek 没有公开。现在能确定的只有边界：提升发生在后训练；不能把功劳擅自归给某一种算法。

这也解释了为什么 Agent 能力可能突然跃升。很多失败并不是模型“不懂”，而是它没有学会在几十步操作中稳定地把知识用出来。

Agent 时代，还有一组藏在模型外的参数

这次发布里最容易被忽略的词，是 DeepSeek Harness。

Harness 可以翻成“驾驭系统”。它负责把模型装进真实工作环境：给它哪些工具，怎样描述代码仓库，命令失败后如何恢复，上下文什么时候压缩，改完是否强制跑测试，什么时候继续，什么时候停。

如果模型是发动机，Harness 就是变速箱、轮胎、导航和刹车。

只比发动机马力，已经看不懂一辆 Agent 到底跑得多快。

官方也写得很清楚：这批 Code Agent 成绩使用了尚未发布的 DeepSeek Harness minimal mode，并开启 max effort，测试参数包括 top_p=0.95 和 temperature=1.0。

所以，82.7 是**“V4 Flash 0731 + DeepSeek Harness”组合在官方自测中的成绩**，不能简单拆成“模型权重单独值 82.7 分”。4 月预览版用的是 Terminal-Bench 2.0，这次用的是 2.1；2.1 修复了 89 道任务中的 28 道，多数代表性 Agent—模型组合在 2.1 中涨分。网上流传的直接相减涨幅，并不严谨。

这不是给成绩泼冷水，反而点出了更重要的趋势：

Agent 的产品单位，已经从一个模型，变成基座模型 × 后训练 × Harness × 推理预算。

同一个模型放进不同的工具集、提示词、上下文管理和错误恢复机制里，可能像两位完全不同的工程师。未来我们看到的，也许不再是单独的“模型发布”，而是模型与 Harness 配对发布。

接进 Codex，DeepSeek 抢的是入口

V4 Flash 0731 原生支持 Responses API，并针对 Codex 做了适配。

这件事听起来像接口更新，实际碰的是 Agent 生态的入口。

Responses API 把消息、推理过程、工具调用和流式事件组织成同一种协议。接通之后，Codex CLI、桌面端和 IDE 扩展可以把 DeepSeek 当作模型后端。开发者不用重新造一套 Agent，只需要配置新的提供方，再用自己的任务重新评测。

对普通 SDK 调用，核心信息仍是两项：

base_url = "https://api.deepseek.com"
model = "deepseek-v4-flash"

接进 Codex 还需要配置模型提供方、Responses 协议、API Key 和模型目录，并不是把上面两行粘进去就完事。官方给出了一键脚本与手动配置，两种方式都应先备份原有配置。

官方直连 API 已经指向 0731 版。经由第三方服务调用时，要先核对对方是否完成版本切换；当前公开权重仍是 Preview，也不能把本地部署当成已经用上了 0731。

不过，“支持 Responses API”不等于完整复制了另一套平台的全部能力。

当前主干链路已经能跑：函数调用、服务端网页搜索，以及 Codex 修改代码所需的 apply_patch。但服务端会话状态、后台任务、MCP、computer use、code interpreter、file search、图片和文件输入，还没有接通或会被忽略。麻烦的是，一些不支持的参数会被静默忽略：请求没有报错，不代表配置真的生效。

这更像统一使用 USB-C 接口：插头形状一样，迁移确实容易了；不代表每一根针脚、每一种功能都已经通电。

对开发者来说，这已经够实用。对企业来说，上线前仍要把自己的工具链跑一遍，不能把“协议兼容”当成“行为完全一致”。

真正有杀伤力的，是“完成一次任务”多少钱

Luna 已经降了 80%，DeepSeek 的输入仍便宜 30%，输出便宜约 77%。如果命中缓存，V4 Flash 的输入价格还会降到 0.0028 美元 / 百万 token，只有普通输入的五十分之一。

V4 Flash 这次没有趁升级涨价。这仍是当前价；DeepSeek 已经预告未来会在北京时间部分高峰时段按两倍计费，但生效日期还没公布。

这对 Agent 格外关键。DeepSeek 的上下文缓存命中的是重复 prompt 前缀。把系统提示、项目说明和不变的仓库上下文稳定放在请求前部，多轮任务才更容易命中；语义相近但前缀不同的问题，并不会自动享受这个价格。

公开技术讨论里，关注点也迅速从“它能不能写代码”转向“能不能让它在后台连续跑”。大家真正兴奋的不是省几次对话的钱，而是过去舍不得交给模型的批量工作——补测试、修 lint、迁移接口、整理文档——开始有了持续执行的经济性。

但每百万 token 的标价，不等于完成任务的总成本。模型如果输出冗长、反复重试，或者最终仍要人工接管，再低的单价也会被吃掉。

这次独立评测还有个很少被标题写进去的细节：完成整套测试时，0731 总共输出约 2.06 亿 token，旧版约为 2.34 亿，下降 12%。它分数更高，话却更少。对按输出量付费、还要承担延迟的 Agent 来说，这比“又便宜了几厘”更实在。

以后选 Agent，不该只看智力分数，而要看一次合格交付的成本。

这会催生一种更实际的分工：强模型负责澄清需求、架构设计、安全审查和最终验收；便宜、快速的模型负责读文件、批量修改、跑测试和修小错。人保留合并代码与生产变更的批准权。

过去，开发者问“哪个模型最好”。

接下来要问的是：哪一步值得叫最贵的模型，哪一步交给便宜模型就够了？

它很强，但还不是“全能冠军”

V4 Flash 0731 的定位其实很清楚：便宜、快速、长上下文，工具调用突出，适合文本型 Coding Agent 和高频自动化任务。

它的边界也同样清楚。

在更强调陌生仓库、长程工程的 DeepSWE 上，54.4 仍与顶级闭源模型有距离；它没有图像输入，前端截图排错和通用电脑操作会受限；官方 Harness 尚未发布，第三方框架里的稳定性、延迟和重试成本还要靠真实项目验证。

独立评测也泼了一盆很有价值的冷水。在 AA-Omniscience 上，0731 的综合可靠性指数从 -23 改善到 -16，但知识准确率仍是 37%，没有比旧版更高；幻觉率则降至 84%。



图源：Artificial Analysis。84% 是该机构在 AA-Omniscience 特定方法下测得的幻觉率，不代表所有场景。

这组结果至少提示：在这套测试里，新版未必“知道得更多”，但更少把不知道的事说成真的。至于这种变化来自哪些训练数据和奖励规则，官方没有披露，不能反推。可 84% 依然很高，离“幻觉已经解决”差得远。需要事实准确性的工作，检索、引用和人工复核一个都不能省。

如果代码、日志或凭证涉及敏感数据，低价格也不能代替数据分级与供应商评估。能接入，不等于应该把整个生产仓库原样交出去。

还有一个常见误会：100 万 token 的窗口，代表“能塞进去很多”，不代表“每一处细节都能稳定找对”。长上下文是仓库级 Agent 的入场券，不是正确率保证书。

所以，我不会把这次更新写成“DeepSeek 全面登顶”。

更准确的判断是：官方自测把它送进了 Coding Agent 第一梯队的候选席，第三方评测确认了整体提升；能否站稳，还要看同 Harness、同预算的真实项目复测。

这已经足够改变市场。

因为如果真实项目里的合格交付成本也能显著下降，Agent 才可能从偶尔尝鲜，变成一项一直开着的工程资源。

这不是意气之争，是一场效率消耗战

把两家公司相隔一天的动作放在一起，很容易写成谁在狙击谁。但发布节奏无法证明因果，可以确认的是，它们都在改写同一套公式。

OpenAI 在降价公告里把效率来源拆成模型、推理系统和连接工具与上下文的 Agent Harness；DeepSeek 则用同样的架构与参数规模，经新的后训练和定制 Harness，把一款 Flash 模型推到了更高的位置。

路线不同，考卷却是同一张：在模型能力够用之后，谁能少用 token、少重试、少让人接管，谁就能把 Agent 从偶尔尝鲜变成一直开着的工程资源。

所以，DeepSeek 这次最值得记住的，不是官方的 82.7，也不是第三方的 50。是模型正在从“产品本身”，退回成产品的一块零件。胜负取决于它能否进入你的工作流，能否在出错后继续完成闭环，以及一次合格交付到底花多少钱。

AI 公司接下来卖的，不只是智商，而是完成任务的能力。

如果你想判断 V4 Flash 值不值得接入，别先跑十道算法题。

从团队最近做完的任务里抽 20 个：补测试、修 Bug、跨文件重构各选一些。给不同模型相同权限和验收标准，记录成功率、人工接管次数、总 token、耗时和最终成本。

跑完这张表，你就知道谁真的能干活。
