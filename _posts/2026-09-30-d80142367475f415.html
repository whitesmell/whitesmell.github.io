在旧金山 Fort Mason 的聚光灯打亮前夕，全球开发者社区的预期正被两则关键消息所牵动。

一方面，曾一度暂停新订阅的 200 美元 Pro 套餐重新开放，但内含的 Codex 和 Work 额度下调至 Plus 的 10 倍，高阶模型的使用上限有所收紧；另一方面，《华尔街日报》在会前披露，原定发布的旗舰模型 GPT-6.1 Astra 因在安全评估中仍需对“自主推进任务时的权限边界与透明度”做进一步调校，被临时延后。

订阅策略的结构性调整叠加旗舰模型的推迟，让本届 DevDay 承担了极高的审视压力：在大模型单次对话能力边际效应递减的当下，OpenAI 究竟要拿出怎样的新解法，才能证明生成式 AI 迈向工业化生产的真实价值？

图 ：山姆·奥特曼登台开场。在一连串订阅策略微调与模型迭代的关注中，这场发布会成为 OpenAI 展示 Agent 工业化落地的关键窗口。

山姆·奥特曼（Sam Altman）给出的答案，是一个名为 Dots 的常驻智能体（Always-on Bot），以及围绕其展开的 20 余项系统级更新。

整场发布会虽然技术密度极高，但主线逻辑十分清晰：对话框只是大模型技术普及的起点，委托与协作才是生产力落地的重心。OpenAI 正在告别单纯依赖聊天框的单点工具形态，全面转向由常驻 Bot、动态协作空间 Space、低成本推理底座 GPT-6.1 Sol 与统一结算体系构成的下一代计算平台。

一、 交互形态演进：从单次应答 Bot 到全天候“数字同事”

过去三年，人机协同的主流形态基本停留在“人类输入 Prompt、模型返回 Response”的被动交互模式中。窗口一旦关闭，任务状态和上下文往往随之中断。

Dots 的登场，标志着人机交互正在向“委托式代办”（Delegation）加速演进。

每个 Dot 都是由 GPT-6 Astra 驱动的常驻 Bot，拥有独立的云端沙箱环境、专属浏览器会话，以及通过 4000 多个插件调度外部工具的系统权限。用户只需为其划定工作职责，Dot 就会在后台持续跟进长周期任务，仅在遇到关键分歧、缺乏明确指令或涉及高危操作时，才会主动唤醒用户进行确认。

图 ：不同形态与性格的 Dots。OpenAI 试图将其塑造为各司其职的“数字同事”，以拟人化外壳降低复杂系统的协作门槛。

官方展示的业务闭环非常明确：在日常运营中，负责财务追踪的 Bot 会自动比对账目并拟好待开票据；在工程研发中，一旦代码库即将停用旧接口，Bot 会自主梳理依赖关系、修改代码、执行测试套件，并直接将代码合并请求（PR）提交给工程师复核。

在现场实测环节，产品团队负责人 Holly 展示了名为 Dotty 的智能体如何跨越邮件、日历与设计稿，为虚构应用 Blossom 推进上线筹备。

从现场演示来看，长程任务在复杂多端环境下的联动依然充满挑战：无论是跨系统授权切换时的轻微等待，还是调用代码构建进度面板时的偶发延迟，都真实展现出当前的自主智能体技术正处于从实验室走向高可用工程实践的过渡期。

图 ：Holly 现场演示 Dotty 跨应用协调流程。实时多端调用展现了 Agent 处理复杂业务的潜力，也印证了长程任务编排在工程调优上的严苛要求。

事实上，让 AI 从“会话工具”升级为“常驻员工”已经成为全行业的共同探索方向。Meta 的 Muse、xAI 的 Grok Bot 都在加速布局类似形态。相比偏向轻量消费场景的尝试，OpenAI 的重心明显落在了严肃工作流上：

不仅个人 Dot 能直接进驻 Slack 与 Teams 频道接收团队工单，企业级的“专职 Dot”更宣布与微软 Agent 365 展开深度安全与权限集成 。

企业软件每天争夺的“前端停留时长”，正在被无声地解构为后台调用流水。当一个 Bot 能够直接阅读代码库、操作浏览器并沉淀工作上下文时，人机协作的重心便不再是编写精巧的提示词，而是设定明确的验收标准。

二、 算力经济账：GPT-6.1 Sol 撑起长程推理的现实账本

构建全天候运转的智能体，最大的考验不仅是逻辑推理能力，更是持续运行的推理成本账。

如果一个 Bot 需要 7×24 小时监控代码、邮件与业务看板，频繁全量加载长上下文，前沿旗舰模型的高昂调用费足以让任何自动化探索面临严峻的财务压力。

为此，OpenAI 推出了面向日常主力任务的高性价比基座：GPT-6.1 Sol 。

Sol 的工程定位非常清晰：在复杂任务上逼近 Astra 的实用表现，同时将标准 API 价格降至后者的五分之一（输入 2 美元/百万 Token，输出 10 美元/百万 Token）。

更关键的技术突破在于提示缓存（Prompt Caching）的大幅下调：每百万 Token 的缓存输入成本降至 0.10 美元，相较常规输入降低了 95% 。

图：Sol 与 Astra 定价结构对比。标准输入输出价格降低 80%，而缓存输入价格直接降至 0.10 美元/M，大幅缓解长程 Agent 状态复用的成本压力。

对于需要反复读取庞大 Git 仓库、产品规范与多轮历史记录的 Agent 而言，绝大多数 Token 消耗都发生在重复加载相同环境信息的阶段。将缓存输入成本控制在极低水平，企业长周期部署智能体的经济账本才真正具备可行性。

在基准评测中，GPT-6.1 Sol 的表现证明了其在垂直任务上的针对性优化：

  • • 软件工程（DeepSWE 1.1）：在真实仓库级修复场景下，Sol 以五分之一的调用成本追平了 Astra 的上限水准，较前代 Sol 提升 6.4 个百分点；
  • • 文档理解（GDP.pdf）：在复杂长文档处理上展现出显著的成本效益比；
  • • 系统环境操作（OSWorld 2.0）：在计算机操作评测中，Sol 在高推理档位下与 Astra 的差距缩窄至 2.1 个百分点以内，而单任务成本仅为后者的七分之一。
图 ：官方性能-成本权衡图。Sol 在维持接近旗舰模型能力的同时，将单任务推理开销控制在极为陡峭的高性价比区间。

与此同时，OpenAI 带来了全新的 Ultrafast 极速档，将模型的生成速率推升至最高 每秒 300 Token（标准速度的 8 倍），并同步推出基于 Luna 轻量模型的 Decisions API，专门用于毫秒级的界面路由与视觉单步决策。

在现场演示中，高生成速度与轻量决策结合，使得模型能在十几秒内实时完成包含物理特性的 3D 场景代码构建与即时渲染调整。

图 ：Ultrafast 生成对比演示。极速推理不仅缩短了等待时间，更为实时界面接管与动态 3D 渲染提供了可交互的时延基础。

为了匹配不同梯度的计算负荷，OpenAI 调整了订阅矩阵：除重新开放 Pro 200 外，正式上线包含 Ultrafast 权限、提供 25 倍 Plus 用量配额的 Pro 500（500 美元/月） 套餐 。

低成本模型与极速引擎的组合，标志着大模型竞争全面进入工程精细化阶段：GPT-6.1 Sol 负责降低长程调用门槛，Ultrafast 负责压缩等待时延，AI 正在从偶发性的问答系统演进为可与人类工作节拍同步的常驻计算底座。

三、 共享协同空间：ChatGPT Space 与 Living Pages 的办公重构

智能体在后台生成的大量分析图表、修复补丁和过程数据，究竟应该存放在何处？

OpenAI 给出的解法是 ChatGPT Space——一个面向团队与智能体混合办公设计的协同工作区。

图：Space 界面。取代原有的简单对话归档，演进为整合文件、智能体状态与实时产出物的综合工作台。

Space 抛弃了传统聊天窗口“信息流随聊随走”的碎片化形态，引入了以 “Living Pages”（动态活页） 为核心的载体：

  1. 1. 人机协同编辑：人类成员、ChatGPT 与特定的 Bot 能够在同一份文档中实时共同编排；
  2. 2. 文档即运行台：文档支持嵌入可运行的原型、交互式数据看板以及可执行的代码沙盒；
  3. 3. 守护进程注入：页面可以配置周期性自动化指令，例如要求 Bot 每日定时巡检协同渠道，自动将外部新增的异常指标同步到文档表格中 。
图：Living Pages 动态交互演示。团队在正文中直接调用反馈数据，右侧的趋势图表无需跳转第三方 BI 工具即可在画布中实时重绘。

过去的办公文档本质上是静态的信息记录，而 Space 试图将其转变为可交互的执行界面。未来的文档不仅记录业务决策，更作为执行调度的载体；协作也不再局限于人与人的文字同步，而是拓展为团队与数字员工之间的动态配合。

四、 平台化闭环：“用 ChatGPT 登录”与算力结算中心

如果说模型降价与工作区是在加固产品体验，那么大会压轴公布的生态策略，则展现了 OpenAI 构建底层平台级枢纽的布局。

这套体系的核心由三部分组成：

  1. 1. “Sign in with ChatGPT”（使用 ChatGPT 登录）：过去开发者构建垂直 AI 应用，最大的阻力在于必须承担高昂的 API 预付账单，再转嫁给用户。现在，用户只要使用 ChatGPT 账号授权登录第三方软件（如首批接入的 Devin、Notion、Vercel 等），即可直接消耗用户自身订阅内包含的 Token 额度。
  2. 2. Plugin Extensions（原生插件扩展）：Adobe、Figma 等行业工具不再只是幕后 API，而是能将自身专业的操作看板原生地嵌入到 ChatGPT 和 Codex 的操作界面中。
  3. 3. OpenAI Marketplace：一个依托 12 亿周活跃用户的官方分发生态，企业客户可以直接用与 OpenAI 签订的年度算力合同预算，采购生态伙伴的专业工具与企业服务。
图：连接第三方工具的操作界面。用户将自身账户算力打通至垂直应用，降低了中小团队自建跨境计费与模型垫资的门槛。
图：首批 30 余家合作伙伴矩阵。涵盖开发、数据分析与安全管理，标志着以 ChatGPT 为算力清算核心的商业链路正在形成。

这一机制在很大程度上重构了 AI 应用的分发逻辑：

  • • 对垂直应用开发者：获客门槛大幅降低，无需再为用户的试错算力承担高昂的早期垫资风险；
  • • 对付费用户：高级订阅中的算力额度获得了更广泛的跨平台消耗场景；
  • • 对 OpenAI：它进一步巩固了“算力结算中心”的地位，使更多外部应用在底层与自身的账户和模型体系产生深度绑定。

当用户能够使用统一的 Token 余额跨应用消费时，应用生态可以在垂直场景百花齐放，而底层算力的价值沉淀则进一步向中心集聚。

尾声：在效率跃迁与治理边界之间

发布会临近尾声，现场安排了一个充满社区趣味的互动环节：一位曾长期调侃官方额度机制的社区开发者被邀请上台，奥特曼与他共同按下一台象征性的“实体重置按钮”，为现场所有开发者的账户额度完成了一次即时刷新。

图：奥特曼与社区开发者共同按下“重置按钮”。在这场充满仪式感的人机互动背后，折射出行业在算力调度与使用成本上的长期平衡。

在随后的结语中，奥特曼再次分享了他对人机未来的愿景：

“人们常常把 AI 比作新的工业革命。但我更希望它是一次‘新文艺复兴’。工业革命把人变成复杂机器中的齿轮，要求你运转得更快；而 AI 的真正价值，应该是把人类从机械琐碎的劳动中解放出来，赋予每个人更多掌控力，去探索那些本就不该被自动化的创造力。”

这段总结道出了技术演进的人本初衷，但技术向真实工序渗透的过程，同样对系统边界提出了更严肃的要求。

正如会前被审慎延后发布的 GPT-6.1 Astra 所揭示的工程现实：当智能体开始被赋予跨应用执行、自动调度工具与持续推进业务的权力时，“自主执行”与“受控安全”之间的平衡，将成为全行业走向深水区时必须直面的课题。

从单次调用的会话框，到全天候跟进任务的个人 Bot，再到由 GPT-6.1 Sol 撑起算力底座、打通多方协同的 Space 工作区，OpenAI 在本届 DevDay 上完成了一次系统性的平台跃迁。技术褪去最初的概念光环、算清每一分工程账目并真正融入生产流程，这一演进才刚刚步入核心章节。
