如果你对人工智能在编程领域的应用感兴趣，或者想了解大语言模型如何改变编程实践，那么这篇博文值得一读。Redis作者antirez作为一名程序员对大语言模型的个人体验，包括它们在加速编码、理解数据、写一次性程序等方面的应用，以及在系统编程中的局限性。这篇文章将帮助你理解大语言模型在编程中的实际应用，以及它们可能对未来编程实践的影响。

Salvatore Sanfilippo，也被称为 antirez，是一位来自意大利西西里的计算机程序员，他主要编写开源软件。他是 Redis, Disque, linenoise 等项目的作者，并在 GitHub 上拥有 20.5k 的关注者。他的代码风格和创新，以及他对 Redis 的影响和贡献，都得到了业界的广泛认可。

Redis 是一个开源的，基于内存的，NoSQL数据存储，主要用作应用缓存或快速响应数据库。它是由 Salvatore Sanfilippo 编写的键值存储系统，是跨平台的非关系型数据库。


我首先声明，本文并非对大语言模型进行回顾。显然，2023年是人工智能的特殊一年，重复这一点似乎毫无意义。相反，本文旨在分享我作为一名程序员对大语言模型的个人体验。自ChatGPT问世以来，我开始广泛使用这项新技术，后来又使用了可以本地运行的大语言模型。我的目标是加快编程速度，但这并不是唯一的目的。我也希望避免在编程中浪费精力于那些不值得花费心力的方面。例如，花费无数小时在一些智力上毫无意思的特殊方面搜索文档；学习一个过于复杂的 API 的努力，这往往没有好的理由；编写可以立即使用但几小时后就会丢弃的程序等等。有了谷歌搜索引擎变成垃圾信息海洋的今天，我不想做这些事情，尤其是现在，只需要在其中寻找一些有用的东西。

同时，我当然不是编程新手。我有能力没有任何帮助就编写代码，而事实上，我也确实这样做得很频繁。随着时间的推移，我在 Python 编程中越来越多地使用大语言模型，尤其是在 Python 中，在 C 语言中就少得多。我对大语言模型的个人经历让我印象最深刻的是，我已经准确地了解到何时使用它们何时它们的使用只会拖累我。我也了解到，大语言模型有点像维基百科和 YouTube 上分散的所有视频课程：它们帮助那些有意愿、能力和纪律的人，但对于那些落后的人来说，它们的好处很小。我担心它们至少在最初只会使那些已经具有优势的人受益。

但让我们一步一步来。


# 大语言模型：创造还是模仿？


这波机器学习新奇性和进步的最令人担忧的现象之一，是 AI 专家接受自己有限知识的有限能力。人类发明了神经网络，然后更为关键的是，发明了一种算法来自动优化神经网络的参数。硬件已经能够训练越来越大的模型，并通过对要处理的数据的统计知识(先验知识)以及通过大量的试错逐步逼近，发现了比其他工作得更好的体系结构。但总的来说，神经网络仍然相当不透明。

面对无法解释大语言模型某些新出现的能力的这种无能为力，本应期待科学家表现出更多谨慎。相反，许多人严重低估了大语言模型，说毕竟它们不过是比较先进的马尔可夫链，最多能够反刍它们在训练数据集中看到的东西的极为有限的变体。然后，在证据面前，这种鹦鹉的概念几乎被普遍撤回。

与此同时，热情的大众赋予大语言模型现实中并不存在的超自然力量。不幸的是，大语言模型最多只能在它们训练期间看到的数据所代表的空间中进行插值：这已经很多了。事实上，它们的插值能力是有限的(但仍然令人惊叹，也出人意料)。哦，要是今天最大的大语言模型能够在它们看到的所有代码所划定的空间内连续插值该多好!即使它们无法产生真正的新颖性，它们也能够取代 99% 的程序员。现实则更为温和，因为它几乎总是如此。大语言模型肯定有能力编写它们没有以完全相同的形式在训练集中看到的程序，展示了将训练集中出现过的不同想法以一定频率混合在一起的某种能力。同时很明显，这种能力目前有深刻的局限性，每当需要细微的推理时，大语言模型会可怕地失败。尽管如此，它们代表了从人工智能萌芽到今天的最大成就。这似乎是不容置疑的。


# 大语言模型的优缺点：知识丰富，推理欠佳


的确：大语言模型最多只能进行很原始的推理，通常不准确，许多时候还伴随着对不存在事实的幻觉。但它们拥有广泛的知识。在编程领域以及有优质数据的其他领域，大语言模型就像知道很多事情的愚蠢奇才。和这样的伙伴进行结对编程(对我来说，结对编程在最一般的意义上就是可怕的事情)会很糟糕：他们会有无稽之谈的想法，我们不得不连续斗争来坚持我们自己的想法。但是，如果这个博学的傻子可以任我们索取并回答我们提出的所有问题，事情就会变化。当前的大语言模型不会带我们走出知识的轨道，但如果我们想攻克一个我们不太熟悉的话题，它们通常可以把我们从绝对无知中提升到可以自己前进的程度。

在编程领域，也许到二三十年前，它们的能力还很难产生什么兴趣。那时你只需要懂几种编程语言，经典算法和那十个基本库就行了。其余的部分你必须自己添加，你自己的智慧，专业知识，设计技能。如果你具备这些要素，你就是一名专业程序员，几乎能做任何事情。随着时间的推移，我们目睹了框架、编程语言、各种库的爆炸式增长。一个常常完全不必要和不合理的复杂性爆炸，但事实就是如此。在这样的背景下，一个知道很多事情的白痴就是一位宝贵的盟友。  

让我举个例子：我对机器学习的实验至少进行了一年，使用的是 Keras。然后由于各种原因，我转到了 PyTorch。我已经知道什么是嵌入或残差网络，但我并不想逐步学习 PyTorch 的文档(就像我对 Keras 做的那样，那时候 ChatGPT 还不存在)。有了大语言模型，用 Torch 编写 Python 代码变得非常容易。我只需要对要组装的模型有清楚的想法，并提出正确的问题。


# 大语言模型助力开发：加速编码与理解数据


我不会讨论一些简单的事情，比如：“嘿，类X的做Y的方法是什么”?如果只是为了这个，人们可能会倾向于同意那些对大语言模型持怀疑态度的人。复杂型号能做的比这更多。几年前，这还是纯粹的魔法。我可以告诉 GPT4：看，这是我在 PyTorch 中实现的神经网络模型。这些是我的 batch。我想调整张量的大小，以便生成 batch 的函数与神经网络的输入兼容，并且我想以这种特定的方式表示事物。你能给我展示所需的重塑代码吗?GPT4 写出代码，我所要做的只是在 Python CLI 中测试张量是否真的具有对我有用的维度，并且数据布局是否正确。

这是另一个例子。不久前，我需要为某些基于 ESP32 的设备实现 BLE 客户端。经过一些研究，我意识到跨平台蓝牙编程绑定更或少都无法使用。解决方案很简单，使用 macOS 的本机 API 在 Objective C 中编写代码。所以，我发现自己同时需要解决两个问题：学习 Objective C 麻烦的 BLE API，这充满了我认为无意义的模式(我是一个极简主义者，那种 API 与我认为的“良好设计”的对立面);同时记住如何用 Objective C 编程。我上次用 Objective C 写程序是十年前的事了：我不记得事件循环、内存管理的细节等等。

代码的大部分是通过在 ChatGPT 上进行剪切和粘贴来完成的，对于我想做但不太清楚如何做的事情，所以它们无法很好地工作。让大语言模型向我解释问题所在并如何解决它。的确，大语言模型没有写很多代码，但它显然极大地加速了码字。没有 ChatGPT 我能做到吗?当然可以，但最有趣的不是它花了我更长的时间这一事实：事实是即使能做到，我也不会尝试，因为不值得。这一点至关重要。编写这样一个次要程序的努力与收益之间的比率将不方便。此外，这比程序本身有更有用的副作用：为那个项目，我修改了 linenoise(我的一行编辑库之一)，使其在复用中工作。  

再举一个例子，这次更少关于写代码，更多关于解释数据。我想用一个在线找到的卷积神经网络设置一个 Python 脚本，但它的文档相当匮乏。该网络的优点是 ONNX 格式，所以我可以轻松提取输入和输出列表及其分配的名称。我只知道这个卷积核网络一件事：它在图像内检测某些特征。我不知道输入图像的格式和大小，特别是网络的输出远比我想象的要复杂得多(我认为它是一个二进制分类器：观察到的图像OK还是有问题?两个输出，但实际上有数百个)。我开始将 ONNX 网络元数据输出复制粘贴到 ChatGPT 中。我向助手解释我对网络了解甚少的情况。ChatGPT 假设输入是如何组织的，并且输出很可能是标准化的框，指示图像中与潜在缺陷相关的部分，以及指示这些缺陷的可能性的其他输出。经过几分钟的反复，我已经有了一个 Python 脚本，能够进行网络推理，以及将初始图像转换为适合输入的张量所需的代码等等。那次会话让我印象深刻的地方在于，ChatGPT 最终在观察测试图像的原始输出值(基本上是logit)时“理解”了网络的作用方式：一系列浮点数提供了识别确切输出细节、标准化的上下文，如果框是否居中或指定左上角等等。

# 人机协作：大语言模型时代编程的新范式  


遗憾的是，这是真的：今天的大部分编程包含以稍微不同的形式反刍同样的东西。不需要很高的推理水平。大语言模型在做这件事方面相当出色，尽管它们仍然严重受限于上下文的最大大小。这真的应该让程序员思考。编写这种程序值得吗?当然，你会得到报酬，而且相当可观，但如果大语言模型可以做这部分，那么五或十年内这可能不是最好的去处。  

那么，大语言模型有某种推理能力，还是这全都是骗局?有时，它们看起来像在推理，只是因为，正如符号学家会说的那样，“指称者”给人一种实际上并不存在的意义的印象。那些已经足够了解大语言模型的限制并接受这些限制的人确确实实知道不可能如此：它们将之前见过的东西混合在一起的能力远远超出了随机反刍单词。尽管它们的预训练在很大程度上是在预测下一个标记的过程中进行的，但这个目标迫使模型创建某种抽象模型。这个模型是软弱的、不完整的和不完美的，但如果我们观察到我们观察到的，它一定存在。如果我们的数学确定性令人怀疑，最伟大的专家经常持相反立场，那么相信自己亲眼所见似乎是一种明智的做法。

最后，在今天不使用大语言模型进行编程有什么意义呢?向大语言模型提出正确的问题是一项基本技能。越少实践，就越少能够通过 AI 改进工作。然后，发展描述问题的能力对于与其他人交谈也很有用。大语言模型不是唯一的，有时候不明白我们要说什么。沟通欠佳是一个巨大的局限，而许多程序员尽管在各自的领域很能干，但沟通得很差。现在谷歌搜索无法使用了：即使只是作为压缩形式的文档使用大语言模型也是一个好主意。就我个人而言，我会继续广泛使用它们。我从来没有喜欢学习一个古怪的通信协议或一个图书馆的千奇百怪的方法的细节，这通常是由想展示自己有多好的人编写的。在我看来这就是“垃圾知识”。大语言模型每天都在帮我避免所有这些。
