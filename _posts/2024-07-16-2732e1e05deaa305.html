引言：TLDR；

微软研究院最新力作：SPREADSHEET LLM 框架，携手 SHEET COMPRESSOR 编码方法，革新大型语言模型对电子表格数据的处理能力！压缩率高达 25 倍，电子表格表检测和问答任务表现优异，为智能化数据分析开辟新道路！

电子表格，作为数据管理的基石，在当今信息时代扮演着至关重要的角色。从简单的个人预算到复杂的企业财务报表，电子表格的应用无处不在。然而，传统的大型语言模型 (LLM) 在处理电子表格数据时却面临着巨大的挑战。

微软研究院最新发表的论文 “SPREADSHEET LLM: Encoding Spreadsheets for Large Language Models” 直面挑战，提出了一种全新的解决方案。该论文指出，电子表格固有的二维布局、扩展网格以及单元格地址和格式等特定功能，都成为了制约 LLM 理解和分析电子表格数据的关键因素。

电子表格的特点是其广泛的二维网格、灵活的布局和多样化的格式选项，这对大型语言模型 (LLM) 提出了重大挑战。-- SPREADSHEET LLM: Encoding Spreadsheets for Large Language Models

为了解决这一难题，微软研究院的科学家们开发了 SPREADSHEET LLM 框架，并结合创新的 SHEET COMPRESSOR 编码方法，为 LLM 解锁电子表格数据分析新能力。

SHEET COMPRESSOR：高效压缩，释放 LLM 潜能

SHEET COMPRESSOR 是一种专门为 LLM 设计的电子表格编码方法，其核心目标是在保留关键信息的同时，最大限度地压缩电子表格数据，使其能够被 LLM 高效处理。SHEET COMPRESSOR 包含三个相互独立但又可以灵活组合的模块：

1. 基于结构锚点的提取 (Structural-anchor-based Extraction)

大型电子表格通常包含许多同构的行或列，这些行或列对理解其布局和结构的贡献很小。-- SPREADSHEET LLM: Encoding Spreadsheets for Large Language Models

大型电子表格中往往包含大量同构的行或列，例如连续的数值数据或重复的文本标签。这些信息虽然占据了空间，但对理解电子表格的整体布局和结构贡献甚微。

为了提高效率，SHEET COMPRESSOR 首先使用基于结构锚点的提取模块来精简数据。该模块的工作原理是识别并保留那些包含异构数据、能够提供关键布局信息的行列，我们称之为“结构锚点”。例如，表格的标题行、包含不同类别标签的列以及位于表格边界处的行列都可以被视为结构锚点。

图 2: SHEET COMPRESSOR 框架示意图。

如图 2 所示，基于结构锚点的提取模块首先识别出电子表格中的结构锚点（图 2b），然后根据预设的阈值，保留距离锚点一定范围内的行列，并丢弃其他区域的行列（图 2c）。这种方法能够在保留关键布局信息的同时，有效地压缩电子表格的大小，为后续处理减轻负担。

2. 反向索引转换 (Inverted-index Translation)

传统的电子表格编码方法通常采用逐行或逐列的序列化方式，将电子表格数据转换为线性文本序列。然而，这种方法在处理包含大量空单元格和重复值的电子表格时效率低下，会导致 token 数量激增，影响 LLM 的处理速度和效果。

电子表格通常包含许多空行、列和分散的单元格。标准编码方法 (...) 采用基于网格的方法，将单元格地址与其内容配对。这种方法需要记录空单元格以维护电子表格的二维结构，这会显着增加 token 的消耗。-- SPREADSHEET LLM: Encoding Spreadsheets for Large Language Models

为了解决这一问题，SHEET COMPRESSOR 引入了反向索引转换模块。该模块摒弃了传统的线性序列化方式，而是采用一种基于字典的表示方法。

具体来说，反向索引转换模块会将单元格的值作为键 (key)，将对应的地址（或地址范围）作为值 (value)，构建一个字典来表示电子表格数据。

例如，对于以下电子表格：


ABC
1产品价格数量
2苹果105
3香蕉510
4橙子87

反向索引转换模块会将其转换为如下字典：

{
  "产品":"A1",
"价格":"B1",
"数量":"C1",
"苹果":"A2",
"10":"B2, C3",
"5":"B3, C2",
"香蕉":"A4",
"橙子":"A5",
"8":"B5",
"7":"C5"
}

通过这种方式，SHEET COMPRESSOR 不仅能够有效地处理空单元格，还能够将具有相同值的单元格合并在一起，从而显著减少所需的 token 数量，提高编码效率。

3. 数据格式感知聚合 (Data-format-aware Aggregation)

在电子表格中，相邻的单元格通常共享相同的数据格式，例如日期、货币或百分比。SHEET COMPRESSOR 的数据格式感知聚合模块利用这一特点，将具有相似格式的相邻单元格聚合在一起，并用一个代表性的格式字符串来表示，从而进一步压缩数据。

在电子表格中，相邻的单元格通常共享相同的数据格式。(...) 相反，数据类型对于理解电子表格至关重要。(...) 另一方面，与详细的数值相比，相同的数据类型可以通过聚类进行压缩，从而减少 token 的数量。-- SPREADSHEET LLM: Encoding Spreadsheets for Large Language Models

例如，以下电子表格：


AB
1日期销售额
22023-07-18$1,000
32023-07-19$1,500
42023-07-20$1,200

经过数据格式感知聚合模块处理后，可以表示为：

{
  "日期": "A1",
  "yyyy-MM-dd": "A2:A4",
  "销售额": "B1",
  "$#,##0.00": "B2:B4" 
}

这种聚合方式在保留关键语义信息的同时，进一步压缩了数据表示的长度，减少了 token 数量。

电子表格链 (CoS)：拓展应用，赋能下游任务

为了将 SPREADSHEET LLM 的能力应用于更广泛的下游任务，例如电子表格问答、公式预测等，微软研究院的科学家们还提出了一种名为“电子表格链 (CoS)”的方法。

图 1: SPREADSHEET LLM 流程图。

CoS 方法将电子表格推理过程分解为两个阶段：

1. 表格识别和边界检测

为了将 SPREADSHEET LLM 的适用性扩展到更广泛的下游任务，我们引入了电子表格链 (CoS)，它分为两个阶段：表格识别和边界检测。最初，将压缩后的电子表格和特定任务查询输入到 LLM 中。-- SPREADSHEET LLM: Encoding Spreadsheets for Large Language Models

当用户提交一个与电子表格相关的查询时，CoS 方法的第一阶段会利用 SPREADSHEET LLM 的语义理解能力，从复杂的电子表格中准确识别出与该查询相关的表格，并确定其边界。

2. 响应生成

响应生成：将查询和已识别的表格部分重新输入到 LLM 中。然后，模型处理此信息以生成对查询的准确响应。-- SPREADSHEET LLM: Encoding Spreadsheets for Large Language Models

在识别出相关表格后，CoS 方法的第二阶段会根据具体的任务类型，生成相应的响应。例如：

  • • 对于电子表格问答任务，CoS 方法会根据相关表格的内容，生成对用户查询的答案。

  • • 对于公式预测任务，CoS 方法会根据相关表格的结构和数据模式，预测用户想要输入的公式。

总结：展望未来，开启智能数据分析新篇章

微软研究院提出的 SPREADSHEET LLM 框架和 SHEET COMPRESSOR 编码方法，为 LLM 处理和分析电子表格数据开辟了新的道路。

  • • SHEET COMPRESSOR 通过有效压缩电子表格数据，解决了 LLM 在处理大型电子表格时面临的挑战，为 LLM 在电子表格数据分析领域的应用扫清了障碍。

  • • CoS 方法则将 SPREADSHEET LLM 的能力扩展到更广泛的下游任务，例如电子表格问答、公式预测等，为电子表格数据的智能化应用提供了更多可能性。

SPREADSHEET LLM 的优势：

  • • 高效性: SHEET COMPRESSOR 编码方法能够显著减少 LLM 处理电子表格数据所需的 token 数量，提高处理效率。

  • • 准确性: 实验结果表明，SPREADSHEET LLM 在电子表格表检测和问答等任务上都取得了优于现有最先进方法的性能。

  • • 可扩展性: CoS 方法使得 SPREADSHEET LLM 能够应用于更广泛的下游任务，例如电子表格问答、公式预测等。

相信随着 SPREADSHEET LLM 的发展和完善，LLM 在电子表格数据分析领域的应用将会越来越广泛，为我们带来更加智能化的数据体验。
