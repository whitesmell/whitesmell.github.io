    2026 年 4 月 24 日，DeepSeek-V4 预览版上线并同步开源。官方发布页写得很直接：DeepSeek-V4 预览版正式上线，迈入“百万上下文普惠时代”；用户可以在 Chat 端通过 Expert Mode / Instant Mode 体验，也可以通过 API 将 model 参数改为 deepseek-v4-pro 或 deepseek-v4-flash 直接调用。

    这次发布真正值得关注的，不只是一个更强模型，而是一套新的效率范式。

    过去一年，大模型竞争的主线是“谁更聪明”。DeepSeek-V4 把问题往前推了一层：当模型能力接近前沿之后，谁能把强能力变得更便宜、更稳定、更可部署？

    这也是整份技术报告的核心气质：不是靠更大参数硬冲，而是从注意力、MoE、残差、优化器、KV 缓存、后训练和 Agent 基础设施一起重写成本结构。

    一、模型矩阵：同一场效率革命的两个刻度

    DeepSeek-V4 同时发布 Pro 和 Flash 两个版本。它们不是简单的“高配 / 低配”，而是在探索两个不同问题：

    V4-Pro 追问的是：在这套新架构下，推理能力和 Agent 能力的上限在哪里？
    V4-Flash 追问的是：当参数和激活规模显著缩小后，能否保留足够强的能力，并把长上下文成本压到足够低？

    官方文档显示，deepseek-v4-flash 与 deepseek-v4-pro 均支持 1M 上下文、最大 384K 输出、JSON Output、Tool Calls、Chat Prefix Completion；FIM Completion 仅支持非思考模式。

    这组对比最重要的不是“Pro 有 1.6T 参数”，而是 MoE 的激活效率：Pro 每次只激活 49B 参数，Flash 只激活 13B 参数。换句话说，模型拥有巨大的知识容量，但每次推理只支付一小部分计算账单。

    • • 复杂推理、代码仓库级 Agent、长链路任务，用 Pro；
    • • 常规问答、客服初筛、知识库查询、内容草稿，用 Flash；
    • • 高价值复杂任务，开启 Thinking High / Max；
    • • 低延迟高并发任务，优先 Non-Thinking 或 Flash。

    二、百万上下文从何而来：数据配方与长序列训练

    长上下文能力不是在推理阶段“打开一个参数”就能得到的。它必须从数据、训练课程和注意力结构开始共同构建。

    2.1 数据配方：想让模型看千里，先喂它走百里

    技术报告显示，DeepSeek-V4 的预训练语料超过 32T tokens，并且在 V3 数据基础上特别扩展了长文档、多语言、数学、代码等高质量数据。报告还提到，V4-Flash 与 V4-Pro 分别在 32T、33T tokens 上完成预训练，并原生支持 1M 上下文。

    这里有一个第一性原理判断：

    模型不可能稳定掌握训练数据中几乎不存在的依赖模式。

    如果训练语料主要是短文本，模型就很难真正学会跨章节、跨文件、跨任务轨迹的推理。V4 扩充长文档数据，本质上是在让模型从预训练阶段就习惯长程依赖。

    更值得注意的是，V4 在训练中引入了面向 Agent 场景的数据，包括工具调用、多轮交互和代码轨迹。这一点对后续 Agentic Coding 很重要：如果模型在预训练中从未见过工具调用格式和长链路交互，后训练就像在空白画布上补课，能力会更加脆弱。

    数据处理上，V4 继续使用 Fill-in-Middle 策略，并采用样本级注意力掩码，让每个样本独立计算注意力，不同样本之间互不可见，避免跨文档信息泄漏。

    2.2 渐进式训练：先学会正常看，再学会在压缩里看

    百万上下文不是一步训练出来的，而是分阶段推进：4K → 16K → 64K → 1M。

    这条训练路线最关键的节点发生在 64K 阶段：V4 不是一开始就让模型直接进入稀疏注意力，而是先用稠密注意力训练前 1T tokens，让模型先学会稳定的注意力模式；随后再启动 CSA 的 Lightning Indexer 预热，让索引器学习如何在压缩块中选择相关信息；最后才进入更长上下文和稀疏模式。

    这就是“先稠密，后稀疏”的课程学习。

    它解决的是长上下文训练的核心矛盾：模型需要长上下文来学习长程依赖，但长上下文训练本身又极其昂贵。V4 的做法是先让模型学会“如何正确关注”，再教它“如何在压缩空间中高效关注”。

    这不是简单工程技巧，而是一种训练哲学：不要让模型一上来就在压缩世界里盲选，先让它在完整世界里学会判断。

    三、架构全景：沿一次前向传播拆解效率的来源

    DeepSeek-V4 的推理流水线可以概括为：

    输入 Token → 嵌入 → CSA/HCA 混合注意力 → DeepSeekMoE → mHC 残差混合 → MTP → 预测头

    这条路径上，每个模块都围绕同一个问题展开：

    如何尽量接近全量注意力的效果，却只付出几分之一的计算代价？

    【Figure 2｜DeepSeek-V4 整体架构图】

    3.1 CSA 与 HCA：把注意力拆成三种“焦距”

    自然语言里的依赖关系不是单尺度的。

    相邻 token 之间有强语法约束；段落内部有主题连贯性；跨章节、跨文件、跨工具调用历史，则存在稀疏但关键的长程语义关联。传统 attention 却用同一套 O(n²) 机制处理所有依赖，相当于拿同一焦距的镜头拍所有景物。

    DeepSeek-V4 将注意力拆成三种“焦距”：

    第一，滑动窗口：负责短程细节。
    窗口大小为 128，用来覆盖最近 token 的局部依赖。这里信息密度最高、语法关系最细，所以保留相对完整的局部注意力。

    第二，CSA：负责中距离主题关联。
    CSA，即 Compressed Sparse Attention。它先将每 4 个 token 的 KV 缓存压缩成一个条目，再通过 Lightning Indexer 选择最相关的压缩块。技术报告描述，CSA 会把 KV entries 压缩到 1/m，再结合 DeepSeek Sparse Attention，每个 query 只关注部分压缩 KV 条目；同时还会加入滑动窗口 KV 来补充局部细粒度信息。

    可以把 CSA 理解成每层注意力里的“微型检索引擎”：先粗筛，再精读。

    第三，HCA：负责超长程全局弱信号。
    HCA，即 Heavily Compressed Attention。它把每 128 个 token 的 KV 缓存压缩成一个条目，然后对高度压缩后的全局信息做 dense attention。HCA 不追求细节，而是确保模型不会漏掉那些跨越数万 token 的弱关联。

    因此，V4 的注意力不是“压缩越多越好”，而是不同尺度采用不同策略：

    • • 短程：保留细节；
    • • 中程：压缩 + 稀疏选择；
    • • 超长程：高度压缩 + 全局感知。

    这套混合架构带来了决定性效率变化：1M 上下文下，V4-Pro 单 token FLOPs 仅为 V3.2 的 27%，KV cache 为 10%；V4-Flash 进一步降低到 10% 和 7%。报告还指出，在 BF16 GQA8 基线下，V4 系列的 KV cache 可降至约 2% 量级。

    几个工程细节进一步放大了效率：

    • • 共享 KV + MQA：压缩后的 KV 由多个查询头共享，使缓存大小与头数解耦。
    • • 分组输出投影：将高维 attention 输出先分组投影，再合并回隐藏维度，降低矩阵乘法成本。
    • • 重叠压缩：压缩块融合相邻块边界信息，减少块切分带来的信息断裂。
    • • 稳定性套件：Attention Sink、Query/KV 归一化、Partial RoPE 等机制共同降低长序列分数爆炸风险。

    3.2 DeepSeekMoE：万亿参数的“专科化”表达

    经过注意力层后，信息进入 DeepSeekMoE 前馈网络。

    MoE 的核心洞察很朴素：不同 token 需要不同类型的知识加工。就像医院里不同病人去不同科室，没有必要让每个 token 都激活所有参数。

    V4-Pro 每层包含 1 个共享专家和 384 个路由专家，Flash 则为 256 个路由专家；每个 token 只激活 6 个专家。这使 Pro 可以拥有 1.6T 总参数容量，但每次推理实际计算只对应 49B 激活规模。

    V4 在 MoE 稳定性上做了几项调整：

    • • Sqrt(Softplus(·)) 替代 Sigmoid：让专家亲和力分布更平滑，抑制少数专家过度被选中的马太效应。
    • • 前 3 层使用哈希路由：训练早期不依赖尚未成熟的可学习路由，先用确定性映射换取稳定输入分布。
    • • 无辅助损失负载均衡：通过动态专家偏置维持负载，而不是强行用大权重辅助损失让所有专家平均工作。

    这背后的原则是：负载均衡不是目的，表达能力才是目的。只要避免极端不均衡，不必强迫所有专家处理同样数量的 token。

    所有路由专家权重采用 FP4 量化存储。报告指出，路由专家参数使用 FP4 精度；在现有硬件上 FP4×FP8 的峰值 FLOPs 与 FP8×FP8 相同，但在未来硬件上理论上还可进一步提升效率。

    3.3 mHC 残差混合：一个可证明的稳定性约束

    深层模型的风险，不只是“学不够”，还有“传不稳”。

    残差信号在几十层、上百层网络中传播时，可能逐层爆炸，也可能逐层衰减。V4 引入的 mHC，也就是 Manifold-Constrained Hyper-Connections，试图给残差连接加上更强的稳定性约束。

    报告描述，mHC 将残差映射矩阵投影到双随机矩阵流形上，并使用 Sinkhorn-Knopp 算法进行行列归一化；这一过程迭代 20 步得到受约束的矩阵。

    双随机矩阵的关键性质是：每行每列之和为 1，元素非负。这样的约束可以让残差变换更接近“非扩张性”映射，从而降低深层信号爆炸或衰减风险。

    这不是简单加一个 normalization，而是从数学约束出发改写残差连接。mHC 的意义在于：大模型稳定性不应只靠经验技巧，也可以通过结构约束给出更强保证。

    3.4 MTP：让模型在每个位置多看几步

    MTP，即 Multi-Token Prediction，是从 V3 延续下来的机制。它要求模型在每个位置不仅预测下一个 token，也学习预测未来多个 token。

    从训练效率看，标准语言模型每个位置只拿到一个监督信号，MTP 则让每个位置获得更丰富的未来监督。它相当于用同样的数据，让模型学习更多短期与中期语言规律。

    MTP 的价值在长上下文里尤其明显：如果模型被迫预测更远 token，就不能只依赖局部模式，而要学习更长距离的结构关系。

    最终，隐藏状态进入 128K 词表预测头，训练损失由标准 LM 损失和 MTP 损失组合而成。

    四、工程骨架：把理论效率兑现到硬件上

    架构决定了“应该怎么做”，工程决定了“能不能真的跑起来”。

    DeepSeek-V4 技术报告最有价值的地方之一，是它没有把系统工程藏在角落，而是把训练、推理、缓存、并行、量化都摆到了台面上。

    4.1 细粒度专家并行：通信消失在计算之中

    MoE 模型的核心瓶颈之一，是跨节点专家通信。

    V4 的做法是把专家切成多个“波次”，让当前波次计算、下一波次通信、已完成结果发送并发执行。报告显示，这种融合式专家并行方案相较非融合基线，在通用推理负载下加速 1.50–1.73 倍，在强化学习推理场景中最高加速 1.96 倍。

    更重要的是，报告给出了一条判断准则：通信能否隐藏，不只取决于带宽绝对值，而取决于计算/通信比。

    这对硬件和系统设计都有启发：与其无止境堆带宽，不如从模型结构和并行策略上提高计算/通信比，让通信“藏”在计算里。

    4.2 FP4 量化与混合 KV 缓存

    百万上下文真正进入产品之前，最大障碍不是“理论上能不能算”，而是 KV Cache 怎么管理。

    V4 的 KV cache 是异构系统。技术报告 Figure 6 显示，V4 将 CSA/HCA 的压缩 KV 放入经典缓存，将滑动窗口 KV 和尚未完成压缩的尾部 token 放入状态缓存。报告还明确指出，传统 PagedAttention 及其变体并不能直接有效管理这种混合缓存，因此需要重新设计 KV cache 布局和稀疏注意力 kernel。

    这说明 V4 的长上下文不是简单扩大窗口，而是重构缓存系统。

    在共享前缀复用上，V4 还设计了 on-disk KV cache storage，用来支持高效共享前缀复用。对企业知识库、代码仓库、长文档 Agent 来说，这一点非常关键：同一批材料被反复读取时，缓存命中率会直接影响产品成本。

    4.3 Muon 优化器：从逐参数调整到矩阵几何约束

    V4 在多数模块中用 Muon 替代 AdamW。Muon 的核心思想，可以理解为不是逐参数地调学习率，而是对参数更新矩阵的整体几何性质施加约束。

    它通过牛顿-舒尔茨迭代，将更新矩阵拉向更接近正交的形态，避免更新在某些方向过度集中。这个思想和 mHC 有相似哲学：不是完全无约束地优化，而是在带几何约束的空间中寻找更稳定的动态。

    在 ZeRO 兼容上，V4 也做了额外工程设计：稠密参数用背包算法均衡分配到有限 ZeRO rank；MoE 参数则把同类专家矩阵展平后均匀切分，梯度同步采用 All-to-All 和本地 FP32 求和，避免低精度累加误差。

    这说明 Muon 并不是“换一个优化器名字”，而是牵动训练框架、并行策略、梯度同步和数值稳定的一套系统工程。

    4.4 训练稳定术：给路由装上“慢半拍”的机制

    万亿 MoE 训练中，损失尖峰几乎是常见诅咒。V4 技术报告坦诚讨论了这个问题，并提出两类策略：Anticipatory Routing 和 SwiGLU Clamping。

    预测性路由的直觉很有意思：异常值会因为路由机制被反复选中，从而形成“异常 → 被选中 → 被放大 → 更容易被选中”的正反馈链路。解决办法不是直接压死路由，而是让路由慢半拍——用几步之前的旧参数来做当前路由决策，从而切断瞬时正反馈。

    报告还提到，预测性路由在工程实现上会带来约 20% 额外开销，但系统只在检测到损失尖峰时短暂激活，稳定后再切回标准训练。SwiGLU Clamping 则通过限制激活范围来减少极端值。

    这里最有价值的判断是：

    MoE 不稳定不只是参数规模问题，更是路由动态反馈问题。

    报告也坦承，这些方法虽然有效，但底层机制仍需进一步研究。这样的坦诚非常重要：它提醒后来者，这里不是“问题已经终结”，而是“工程上先找到了有效药方，理论上仍有深水区”。

    Flash 以 13B 激活规模，在多个指标上超过 37B 激活的 V3.2-Base；Pro-Base 则进一步把 SimpleQA-Verified 从 28.3 推到 55.2。

    这组结果最大的意义，不是某个分数高低，而是证明了一件事：

    结构红利正在超过单纯规模红利。

    过去很多模型改进靠“更大参数、更大数据、更大算力”往前推。V4-Flash 的对比说明：如果注意力、MoE、残差和训练策略更高效，小激活规模也能做出强能力。

    这对开源模型尤其重要。因为开源生态不可能长期只靠最大算力竞赛获胜，它更需要架构效率和部署效率。

    六、后训练新范式：在策略蒸馏与不遗忘的思维链

    V4 的后训练采用“先分后合”的路线：先培养领域专家，再通过在策略蒸馏整合为统一模型。技术报告将这一流程概括为先在数学、代码、Agent、指令跟随等目标领域训练专家，再让统一学生模型通过 reverse KL loss 向教师模型学习。

    这背后的逻辑是：不同能力需要不同奖励信号。数学、代码、工具调用、开放式写作，并不适合全都塞进一个混合 RL 过程里硬训。混合训练容易出现能力干扰，而“先分后合”更像是先让多个专家各自达到高水平，再在输出分布层面融合。

    第一阶段，基座模型在不同领域做 SFT + GRPO，产出领域专家。不同专家还按推理深度分为 Non-Think、Think High、Think Max 三类，以适应不同推理预算。

    第二阶段，统一模型通过全词表反向 KL 蒸馏吸收专家能力。和只对采样 token 做局部对齐不同，全词表 KL 是在完整输出分布层面对齐，更接近“学会老师的偏好结构”，而不是只学某一步的答案。

    第三阶段，V4 加强工具调用和多轮 Agent。报告提到，工具调用采用新的 XML 式格式，以降低转义失败和工具调用错误率；在工具交互任务中，推理历史会被保留，以维持多轮任务中的思维连续性。

    官方 Thinking Mode 文档也强调：思考模式默认开启，支持 reasoning_effort 设置为 high/max；普通请求默认 high，复杂 Agent 请求可能自动设为 max。若思考模式下发生 tool calls，后续所有请求必须完整回传 reasoning_content，否则可能返回 400 错误。

    这意味着 Agent 产品的工程复杂度正在上升。开发者不再只是拼接 messages，而要管理：

    • • final answer；
    • • reasoning_content；
    • • tool calls；
    • • tool results；
    • • 缓存上下文；
    • • 模型路由；
    • • thinking effort。

    V4 的 API 不是简单提供一个模型，而是在把“推理预算管理”推向产品层。

    七、性能实证：从基准到真实场景

    V4-Pro-Max 在多项评测中展现了与前沿闭源模型正面竞争的实力，但这里必须保持克制：它不是所有任务全面超越闭源，而是在多个关键任务上进入了闭源前沿的局部竞争区。

    几个结果尤其值得关注：

    • • Codeforces 3206 rating。报告显示，V4-Pro-Max 在 Codeforces 上达到 3206，并说明其表现与 GPT-5.4 可比，当前排名约相当于人类候选中的第 23 位。

    • 【Figure 8｜形式化数学推理：Putnam-200 / Putnam-2025 评测结果】

    • • SimpleQA 57.9。Figure 1 显示，V4-Pro-Max 在 SimpleQA Verified 上达到 57.9，较前代显著提升。
    • • Agentic Coding 进入可用区间。官方发布页提到，V4-Pro 在 Agentic Coding 评测中达到当前开源模型最佳水平，DeepSeek-V4 已用于公司内部 Agentic Coding 模型；但发布页也明确说，其交付质量仍与 Opus 4.6 思考模式存在一定差距。
    • • Agent 能力仍有边界。报告明确指出，V4-Pro-Max 在公共 benchmark 上与领先开源模型相当，但仍略弱于前沿闭源模型；V4-Flash 在复杂高难任务上也落后于更大的 V4-Pro。

    写汇报、改方案、读材料、查文档、总结会议、输出销售话术、分析客户反馈、梳理竞品信息、把零散材料变成高管能看的判断。


    真正的模型能力，不只体现在“回答是否聪明”，也体现在：

    八、启示与局限：报告中最有价值的判断

    这份技术报告的价值，不只是给出一组成绩，而是提供了几条非常清晰的技术判断。

    1. 压缩注意力是长上下文普及的可规模化路径。
    CSA、HCA、滑动窗口按信息密度分工，把短程细节、中程主题、超长程语义分别处理。这比单纯扩大窗口更接近长上下文的本质。

    2. 架构创新正在超过参数堆积。
    V4-Flash 以更小激活规模超过前代 Base，说明注意力、MoE、残差和训练策略带来的结构红利已经非常可观。

    3. mHC 提供了更强的稳定性思路。
    它不是经验性归一化，而是通过双随机矩阵流形约束让残差信号传播更可控。

    4. Muon 与 mHC 共享同一哲学。
    二者都不是让系统在无约束空间里自由漂移，而是把优化和传播限制在更稳定的几何结构中。

    5. 全词表在策略蒸馏为多专家融合提供了新路径。
    能力不是简单混合数据，也不是粗暴合并权重，而是在分布层面对齐多个专家的偏好和知识。

    6. 工程创新与算法创新同等重要。
    细粒度专家并行、FP4、混合 KV Cache、on-disk cache、Quick Instruction、DSec 沙盒，这些看似“不性感”的基础设施，才是百万上下文从论文走向 API 的关键。

    7. MoE 稳定性要从系统动力学理解。
    预测性路由揭示的不是单点 bug，而是路由选择和参数更新之间的正反馈问题。未来更大规模 MoE 的稳定训练，很可能要继续沿这个方向深入。

    8. 局限写得坦诚，反而增强可信度。
    报告在结论中承认：V4 采用了相对大胆且复杂的架构设计，未来需要进一步去复杂化；Anticipatory Routing 和 SwiGLU Clamping 有效，但底层原理仍需更深入理解；Agent 能力仍与闭源前沿模型存在差距；在线学习等新范式仍处于探索方向。

    官方发布公告结尾写道：

    不诱于誉，不恐于诽，率道而行，端然正己。

    这句话不是技术报告正文，却很适合概括 V4 的气质：不急着讲一个“全面胜利”的故事，而是把已经做出来的、还没完全理解的、仍需改进的，一并摊开。

    这份报告最打动人的，也许不是某个分数，而是它背后的工程哲学：

    先把问题做穿，再把原理补齐；先把系统跑起来，再把架构变得更优雅。

    当百万 Token 的窗口打开，下一个问题已经不只是“模型能读多少”，而是：

    模型如何在线学习？
    Agent 如何长期工作？
    上下文如何变成记忆？
    缓存如何变成成本优势？
    Flash 与 Pro 如何动态路由？
    企业数据如何在权限、引用、审计下进入模型系统？

    DeepSeek-V4 的真正意义，不是宣布开源模型已经全面超越闭源，而是证明了另一件更重要的事：

    开源阵营不再只是追赶者，它正在用效率、透明和工程细节，重新定义大模型演进的参照系。
