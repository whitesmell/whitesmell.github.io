本文介绍了 AI 领域的新兴设计模式——多智能体协作，并探讨了它如何应用于解决复杂任务。通过将任务分解成子任务并分配给不同的 AI 智能体，我们可以像管理团队一样管理 AI，从而提高效率和性能。文章深入分析了多智能体协作的优势和挑战，并介绍了一些相关的框架和工具，例如 AutoGen、Crew AI 和 LangGraph。对于想要探索 AI 应用新可能性的开发者和研究人员来说，本文提供了宝贵的见解和启发。

多智能体协作已经成为 AI 智能体设计中的一个重要模式。对于像编写软件这样复杂的任务，多智能体方法会将任务拆解成更小的子任务，由不同的角色来执行，例如软件工程师、产品经理、设计师、QA ( 质量保证 ) 工程师等等，并让不同的智能体分别完成这些子任务。

我们可以通过提示同一个 LLM ( 大型语言模型 ) 或不同的 LLM 来构建不同的智能体，让它们执行不同的任务。例如，为了构建一个软件工程师智能体，我们可以这样提示 LLM：“你是一位编写清晰、高效代码的专家。编写代码来执行任务……”

虽然我们多次调用同一个 LLM 来执行任务，但却将其视为多个独立的智能体，这种做法可能看起来有些奇怪。以下是一些解释：

  • 这种方法有效！许多团队都在使用这种方法并取得了不错的成果，实践出真知！此外，消融研究 ( 例如，在下面引用的 AutoGen 论文中 ) 表明，多个智能体的性能优于单个智能体。

  • 虽然现在有些 LLM 可以接受非常长的输入上下文 ( 例如，Gemini 1.5 Pro 可以接受 100 万个 tokens )，但它们对长而复杂输入的理解能力参差不齐。通过智能体工作流程，LLM 可以一次只专注于一件事，从而获得更好的性能。通过告诉它何时应该扮演软件工程师的角色，我们也可以指定在该子任务中什么是重要的：例如，上面的提示强调了清晰、高效的代码，而不是可扩展和高度安全的代码。通过将整体任务分解为子任务，我们可以更好地优化子任务。

  • 也许最重要的是，多智能体设计模式为我们开发人员提供了一个框架，可以将复杂的任务分解成更小的子任务。在编写运行在单个 CPU 上的代码时，我们经常将程序分解成不同的进程或线程。这是一个有用的抽象，它让我们可以将一个任务 ( 例如实现 Web 浏览器 ) 分解成更容易编码的子任务。我发现通过多智能体角色进行思考是一个有用的抽象。

在许多公司中，管理人员通常会决定要招聘哪些角色，然后决定如何将复杂的项目 ( 例如编写大型软件或准备研究报告 ) 分解成更小的任务，分配给具有不同专业知识的员工。使用多个智能体也是类似的。每个智能体都实现自己的工作流程，拥有自己的记忆 ( 这本身是智能体技术的一个快速发展方向——智能体如何才能记住足够多的过去交互，以便在即将到来的交互中表现得更好？)，并且可能会向其他智能体寻求帮助。智能体本身也可以参与规划和工具使用。这导致了 LLM 调用和智能体之间消息传递的混乱，从而可能导致非常复杂的工作流程。

虽然管理人员很困难，但这对我们来说是一个足够熟悉的想法，它为我们提供了一个关于如何“雇用”和分配任务给 AI 智能体的思维框架。幸运的是，管理不善的 AI 智能体造成的损害远低于管理不善的人类造成的损害！

像 AutoGen、Crew AI 和 LangGraph 这样的新兴框架提供了丰富的构建多智能体解决方案的方法。如果你有兴趣玩一个有趣的多智能体系统，也可以看看 ChatDev，这是一个运行虚拟软件公司的一组智能体的开源实现。我鼓励你查看他们的 github 存储库，甚至可以克隆存储库并自己运行系统。虽然它可能并不总是能产生你想要的东西，但你可能会惊讶于它做得有多好！

与规划的设计模式一样，我发现多智能体协作的输出质量难以预测。更成熟的反思和工具使用模式更可靠。我希望你喜欢玩这些智能体设计模式，并希望它们能为你带来惊人的结果！
