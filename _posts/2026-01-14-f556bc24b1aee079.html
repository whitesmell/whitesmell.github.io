在 DeepSeek-V2 和 V3 接连以"价格屠夫"姿态震撼业界后，所有人都在问：梁文锋的下一个魔法是什么？

1 月 12 日，DeepSeek 低调开源了 Engram 架构论文。这个由梁文锋团队主导的工作，复活了古老的 N-gram，提出了 "存算分离" 的全新稀疏范式。

它通过 O(1) 的确定性查表，将静态知识从昂贵的 GPU 计算中剥离，支持将千亿参数无损卸载至内存。业界纷纷猜测，这极可能是传说中 DeepSeek V4 突破显存墙的核心底座。

核心发现速览：

  • • 发现了 MoE 与 Engram 间的 U 型分配曲线，最优比例约为 80:20
  • • 记忆扩展在推理任务（BBH +5.0）上的提升大于知识任务（MMLU +3.4）
  • • 100B 参数表卸载到主机内存，吞吐量损失不到 3%
  • • 机制分析证实 Engram 让模型"变深"——浅层等价于基线的深层

第一性原理：梁文锋的"计算剃刀"

DeepSeek 的技术哲学一直是"如无必要，勿增计算"。

让我们看一个反直觉的现象。MIT 和 DeepMind 的研究者用 PatchScope 工具观察，当 Transformer 试图理解 "Diana, Princess of Wales" 这个实体时：

第 1-2 层：只识别出 "Wales" 是个国家
第 3 层：扩展到"欧洲的国家"
第 4 层：理解 "Princess" 的概念
第 5 层：进一步理解"威尔士王妃"这个头衔
第 6 层：终于完整识别"戴安娜王妃（1961-1997）"

这个过程用了整整 6 层 Transformer，消耗数亿次浮点运算。

这是一种极大的浪费。

这种静态的、固定的知识，本质上是一个 查表（Lookup） 问题，而非 推理（Reasoning） 问题。传统的 N-gram 只需 O(1) 时间就能搞定，为什么要用深层神经网络去"模拟"？

类似的"浪费"在 LLM 中无处不在：

  • • 人名地名："Alexander the Great"、"张仲景"
  • • 固定搭配："by the way"、"四大发明"
  • • 代码模板：for (int i = 0; i < n; i++)
  • • 数学公式："E=mc²"

Engram 就是要挥动这把"奥卡姆剃刀"：把"死记硬背"的工作从神经元里剥离，交给哈希表；让宝贵的深层网络，只专注于它最擅长的逻辑推理。

条件计算 vs 条件记忆

当前大模型主要通过 MoE 实现稀疏性：

MoE：根据输入动态选择专家 → 条件计算
优势：在固定计算量下扩展参数
适用：需要上下文理解的动态推理

Engram 提出了互补的思路：

Engram：根据输入查找静态记忆 → 条件记忆
优势：O(1) 检索，不增加计算
适用：固定的、重复出现的模式

这两者处理的是语言建模中两类不同的子任务：

  • • 组合推理：需要深度计算（适合 MoE）
  • • 知识检索：适合静态查找（适合 Engram）

代码透视：从论文到工程的"降维打击"

Engram 的原理听起来简单，但要在 GPU 上高效实现"查字典"，工程难度极大。通过分析开源仓库，我们看到 DeepSeek 工程师如何通过精妙的抽象，将论文思想转化为代码。

Figure：Engram 模块的整体架构

架构设计：两个阶段

检索阶段：

  1. 1. 提取 suffix N-gram（如最后 3 个 token）
  2. 2. 经过词表压缩（语义等价的 token 合并）
  3. 3. 通过确定性哈希映射到嵌入表
  4. 4. O(1) 时间检索静态嵌入

融合阶段：

  1. 1. 用当前隐藏状态 h 作为 Query
  2. 2. 用检索到的嵌入 e 生成 Key 和 Value
  3. 3. 计算语义对齐度 α（类似注意力分数）
  4. 4. 门控融合后经过短卷积输出

关键设计：检索的索引只依赖输入 token，与隐藏状态无关。这意味着可以预先计算，支持预取和通信-计算重叠。

精妙之处二：映射层——实现"确定性查表"

在 NgramHashMapping 类中，我们看到 DeepSeek 对效率的极致追求。他们没有使用传统的 Dict（哈希表太慢且内存不可控），而是设计了 "多头哈希 + 素数取模" 的无锁结构：

# 展示架构思想的伪代码
class NgramHashMapping:
    def __init__(self):
        # 为每个 layer 生成不同的随机乘数（必须是奇数）
        for layer_id in layers:
            multipliers = random_odd_numbers(max_ngram_size)
    
    def get_hashes(self, inputs):
        # 1. 确定性计算：只依赖输入 Token
        mix = inputs[0] * multipliers[0]
        for k in range(1, n):
            mix = XOR(mix, inputs[k] * multipliers[k])
        
        # 2. 软冲突解决：8 个不同素数大小的哈希头
        # 即使 Head 1 碰撞，Head 2-8 也能捞回正确信息
        return [mix % prime for prime in primes]

为什么乘数必须是奇数？ 因为异或哈希时，奇数乘法保证了更好的分布均匀性。

为什么用素数取模？ 素数能最大化减少哈希碰撞的周期性模式。

这段代码揭示了 Engram "存算分离" 的秘密：由于哈希计算只依赖输入，它不需要等待上一层的计算结果。系统可以在计算第 1 层 Transformer 时，就利用 PCIe 带宽，异步预取 第 15 层的记忆数据。

U 型定律：DeepSeek V4 的参数配方？

如果参数预算是固定的，我们应该分多少给"脑子"（MoE），分多少给"笔记本"（Engram）？

DeepSeek 的实验揭示了一条全新的 U 型 Scaling Law：

Figure：左图显示验证损失关于分配比 ρ 的 U 型关系；右图展示 Engram 的幂律扩展

实验设计

定义分配比 ρ：

  • • ρ=1：纯 MoE，所有稀疏参数都是路由专家
  • • ρ=0.8：80% 给 MoE，20% 给 Engram
  • • ρ=0：纯 Engram，没有 MoE

在两个计算预算下（2×10²⁰ 和 6×10²⁰ FLOPs），改变 ρ 时相应调整专家数和嵌入槽数，保持总参数和激活参数不变。

无限扩展的幂律

固定 3B MoE 主干，只扩展 Engram 嵌入槽（从 25 万到 1000 万），验证损失在对数空间严格线性下降。

这意味着：更大记忆持续有收益，不增加计算。

机制揭秘：如何"加深"网络

为什么扩展"记忆"会提升"推理"？论文做了两个深度分析。

LogitLens：预测收敛加速

方法：把每一层的隐藏状态直接投影到词表，看它与最终输出的 KL 散度。散度越小，说明这一层已经越接近最终预测。

Figure：左图为逐层 KL 散度，中图和右图为 CKA 相似度热图

观察：

  • • Engram 模型的 KL 散度曲线整体低于 MoE
  • • 早期层的差距最明显
  • • 下降更陡峭

含义： Engram 模型更快完成特征组合，用更少的层数达到有效预测。

CKA：表征深度对齐

CKA 用来比较不同模型或不同层的表征相似度。论文在 Few-NERD 数据集上提取每层的表征，计算 Engram 和 MoE 各层之间的相似度。

定义"软对齐指数"：对 Engram 的每一层 j，找它在 MoE 中最相似的 top-5 层，计算加权平均位置 a_j。

结果： a_j 系统性地大于 j。

存算分离：打破显存霸权的杀手锏

对于 LLM 部署（尤其是端侧和私有化）而言，Engram 最具颠覆性的特性在于：它打破了 HBM 显存的物理限制。

MoE 的痛点： 路由是动态的，所有专家必须常驻显存。显存大小决定了模型上限。

Engram 的突破： 查表是 确定性 的。我们可以把 100B 甚至 1T 的参数表，扔到便宜的 CPU 内存（RAM） 里。

系统架构

Figure：Engram 的系统实现

训练阶段：

  • • 嵌入表跨 GPU 分片（模型并行）
  • • All-to-All 通信收集激活行

推理阶段：

  • • 嵌入表完全卸载到主机内存
  • • Engram 放在第 2 层和第 15 层
  • • 第 1 层的计算提供时间窗口
  • • PCIe 传输与计算重叠

分层缓存策略：
利用 N-gram 的 Zipfian 分布特性：

  • • 高频嵌入缓存在 GPU HBM
  • • 中频嵌入在主机 DRAM
  • • 低频嵌入在 NVMe SSD

梁文锋手中的三张底牌

Engram 的发布，让我们对 DeepSeek 的技术路线图有了更清晰的认知。梁文锋手中的三张底牌已经明牌：

底牌一：MLA（显存优化）

Multi-head Latent Attention 极致压缩 KV Cache，让 DeepSeek-V3 在长文本场景下依然保持高效。

底牌二：DeepSeekMoE（算力优化）

通过细粒度专家分割和共享专家隔离，极致压榨计算效率。V3 的训练成本仅为同等规模模型的 1/10。

底牌三：Engram（存算分离）

极致优化参数存储，打破显存墙，支持千亿参数无损卸载。

这三块拼图，共同构成了下一代旗舰模型的基础。

如果说 MoE 是为了让模型"算得更快"，那么 Engram 就是为了让模型"记得更多"且"想得更深"。

我们有理由相信，在即将到来的 DeepSeek V4 中，存算分离 将不再是一个学术概念，而是成为标准配置。

技术民主化的新篇章

从更宏观的视角看，Engram 的意义不仅在于技术本身，更在于它指明了一条 技术民主化 的新路径。

传统的大模型军备竞赛，本质上是硬件军备竞赛：

  • • 谁有更多 GPU，谁就能训练更大模型
  • • 谁有更大显存，谁就能部署更强推理

Engram 打破了这个逻辑：不要试图用神经元去拟合整个世界，有时候，一本放在内存里的好字典，比一万个在显存里空转的天才更管用。

这意味着：

  • • 创业公司 可以用较少的 GPU + 大量内存实现高性能部署
  • • 端侧设备 可以用手机的 DRAM 存储海量知识
  • • 私有化部署 不再被显存容量卡脖子

技术的本质，是让稀缺的资源变得不再稀缺。

写在最后

当我们回顾 2024-2026 这两年的大模型进化史，会发现一条清晰的技术演进线：

2024 年初：DeepSeek-V2 提出 MLA，解决了长文本的 KV Cache 瓶颈
2024 年末：DeepSeek-V3 优化 MoE，将训练成本压到极致
2025 年初：Engram 开辟存算分离，打破显存物理限制

这三步棋，步步为营，指向同一个目标：让 AGI 的算力成本降低 100 倍。

这不是一句客套话，而是一个预言。

当 DeepSeek V4 到来时，我们或许会看到：

  • • 万亿参数规模
  • • 百万 token 长文本
  • • 单卡就能推理

那时，我们会意识到，Engram 不是终点，而是起点。
